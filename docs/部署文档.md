# GEO Readiness Checker 部署文档

本文档描述将 GEO Readiness Checker 部署到生产服务器的完整步骤。

- **后端**:FastAPI + Uvicorn,以 systemd 系统服务方式常驻,监听 `0.0.0.0:8070`
- **前端**:Vite 构建后的静态资源,发布到站点目录 `/var/www/html/www.vigilath.com/`
- **数据库**:SQLite,文件位于 `backend/geo_checker.db`,无需独立数据库服务

> 本文档不包含 Nginx、HTTPS 证书与域名解析的配置,假定运维侧已完成 `www.vigilath.com` 的站点接入与反向代理。

---

## 一、环境要求

| 组件 | 版本 | 用途 |
| --- | --- | --- |
| Python | 3.9 及以上(推荐 3.12) | 后端运行时 |
| uv | 最新版 | Python 包与虚拟环境管理(替代 pip / venv) |
| Node.js | 18 及以上(推荐 20 LTS) | 前端构建 |
| npm | 随 Node.js 安装 | 前端依赖管理 |
| systemd | 系统自带 | 后端服务托管 |
| Git | 任意版本 | 拉取代码 |

Ubuntu 服务器一次性安装命令:

```bash
sudo apt update
sudo apt install -y python3 git curl build-essential

# 安装 uv(Astral 出品的高速 Python 包管理器,替代 pip + venv)
curl -LsSf https://astral.sh/uv/install.sh | sh
# 让当前 shell 立即识别 uv;新会话由安装脚本自动写入 ~/.bashrc
source $HOME/.local/bin/env

# 安装 Node.js 20 LTS
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
```

> uv 默认安装到 `~/.local/bin/uv`,部署后续步骤都假定 `uv` 已在 PATH 上。若用 `root` 或其它用户执行 systemd 服务,可用 `sudo install -m 0755 ~/.local/bin/uv /usr/local/bin/uv` 复制到全局路径。

## 四、后端部署

### 4.1 创建虚拟环境并安装依赖

使用 uv 创建虚拟环境并安装 `requirements.txt`:

```bash
cd /home/ubuntu/Dev/geo/backend
uv venv                              # 在 backend/.venv 创建虚拟环境
uv pip install -r requirements.txt   # 安装依赖(比 pip 快 10×~100×)
```

> uv 创建的 `.venv/` 与标准 venv 完全兼容,后续 systemd 服务可直接调用 `.venv/bin/python`,**不需要 uv 在 PATH 上**。
>
> 若以后想升级某个依赖,可用 `uv pip install --upgrade <pkg>`;想看已装清单,用 `uv pip list`。

### 4.2 配置环境变量

创建 `/etc/geo-checker.env`,内容如下(根据实际密钥替换占位值):

```ini
# ---- 基础 ----
DATABASE_URL=sqlite:///./geo_checker.db
SECRET_KEY=请替换为足够长的随机字符串

# ---- 第三方登录 ----
GOOGLE_CLIENT_ID=替换为真实值
FACEBOOK_APP_ID=替换为真实值
FACEBOOK_APP_SECRET=替换为真实值

# ---- 邮件(用于注册验证、找回密码等)----
SMTP_SERVER=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=替换为真实值
SMTP_PASSWORD=替换为真实值
SENDER_EMAIL=替换为真实值

# ---- Stripe(海外信用卡订阅)----
STRIPE_SECRET_KEY=
STRIPE_PUBLISHABLE_KEY=
STRIPE_WEBHOOK_SECRET=
STRIPE_SUCCESS_URL=https://www.vigilath.com/checkout/success
STRIPE_CANCEL_URL=https://www.vigilath.com/checkout/cancel

# ---- AI 引擎 Key(付费检测模式需要)----
OPENAI_API_KEY=
PERPLEXITY_API_KEY=
ANTHROPIC_API_KEY=
```

设置文件权限,避免明文密钥被其它用户读取:

```bash
sudo chown root:root /etc/geo-checker.env
sudo chmod 600 /etc/geo-checker.env
```

### 4.3 执行数据库迁移

首次部署或拉取了新迁移脚本时执行:

```bash
cd /home/ubuntu/Dev/geo/backend
uv run python migrations/001_membership_v2.py
```

> `uv run` 会自动用项目下的 `.venv` 运行命令,等价于 `.venv/bin/python migrations/001_membership_v2.py`,后者也可直接使用。

### 4.4 创建 systemd 服务

新建 `/etc/systemd/system/geo-checker.service`:

```ini
[Unit]
Description=GEO Readiness Checker Backend (FastAPI)
After=network.target

[Service]
Type=simple
User=ubuntu
Group=ubuntu
WorkingDirectory=/home/ubuntu/Dev/geo/backend
EnvironmentFile=/etc/geo-checker.env
ExecStart=/home/ubuntu/Dev/geo/backend/.venv/bin/python -m uvicorn geo.main:app --host 0.0.0.0 --port 8070
Restart=always
RestartSec=3
StandardOutput=journal
StandardError=journal
SyslogIdentifier=geo-checker

[Install]
WantedBy=multi-user.target
```

> 若使用其它运行用户(如 `www-data`),请确保该用户对 `WorkingDirectory` 与 `geo_checker.db` 有读写权限。

### 4.5 启动服务

```bash
sudo systemctl daemon-reload
sudo systemctl enable geo-checker
sudo systemctl start geo-checker
sudo systemctl status geo-checker
```

实时查看日志:

```bash
sudo journalctl -u geo-checker -f
```

### 4.6 验证后端

```bash
curl -i http://127.0.0.1:8070/docs
```

返回 `200 OK` 即表示后端服务已正常运行,可在浏览器打开 `http://服务器IP:8070/docs` 查看 FastAPI 自动生成的接口文档(生产环境建议仅本地访问)。

## 五、前端部署

### 5.1 安装依赖并构建

```bash
cd /home/ubuntu/Dev/geo/frontend
npm install
npm run build
```

构建产物位于 `frontend/dist/`。

### 5.2 发布到站点目录

```bash
sudo mkdir -p /var/www/html/www.vigilath.com
sudo rm -rf /var/www/html/www.vigilath.com/*
sudo cp -r /home/ubuntu/Dev/geo/frontend/dist/* /var/www/html/www.vigilath.com/
sudo chown -R www-data:www-data /var/www/html/www.vigilath.com
```

### 5.3 验证前端

浏览器访问:

```
https://www.vigilath.com/
```

页面正常打开,且能正常调用 `/api/...` 接口,即表示部署完成。

> 若前端无法访问后端接口,请确认运维侧 Nginx 已将 `https://www.vigilath.com/api/` 反向代理到 `http://127.0.0.1:8070/api/`。

## 六、升级与回滚

### 6.1 日常升级流程

```bash
cd /home/ubuntu/Dev/geo
git pull

# 后端:依赖有变化时重装,然后重启服务
cd backend
uv pip install -r requirements.txt
# 如有新迁移脚本
uv run python migrations/001_membership_v2.py
sudo systemctl restart geo-checker

# 前端:重新构建并发布
cd ../frontend
npm install
npm run build
sudo rm -rf /var/www/html/www.vigilath.com/*
sudo cp -r dist/* /var/www/html/www.vigilath.com/
```

### 6.2 回滚

后端回滚:

```bash
cd /home/ubuntu/Dev/geo
git checkout <上一个稳定提交>
sudo systemctl restart geo-checker
```

前端回滚建议在发布前先备份当前站点目录:

```bash
sudo cp -a /var/www/html/www.vigilath.com /var/www/html/www.vigilath.com.bak.$(date +%Y%m%d%H%M)
```

需要回滚时,把 `.bak.*` 目录覆盖回去即可。

## 九、故障排查速查

| 现象 | 排查方向 |
| --- | --- |
| `systemctl start` 失败 | `journalctl -u geo-checker -n 100` 看启动错误,常见为依赖缺失或端口被占 |
| 端口 8070 被占 | `sudo ss -ltnp \| grep 8070`,定位占用进程 |
| 前端 404 / 路由刷新报错 | 确认 Nginx 配置了 `try_files $uri $uri/ /index.html;`(SPA 回退) |
| 前端调用 `/api` 报 502 | 后端服务未启动,或 Nginx 反代地址不是 `127.0.0.1:8070` |
| 数据库表缺失 | 执行 `migrations/001_membership_v2.py` 后再重启服务 |
| 修改 `.env` 后未生效 | 必须 `sudo systemctl restart geo-checker`,systemd 不会热加载 |
