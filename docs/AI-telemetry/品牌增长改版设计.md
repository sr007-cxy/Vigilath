## 3. 左雷达(5 维占比)

- **数据**:`GET /topics/:id/position-breakdown` 返回 `{ top1_pct, top3_pct, top5_pct, visible_pct, source_pct }`,以 `ResponseORM.brand_rank` 为基础聚合
- **行业基准**:`GET /benchmarks/industry?industry=X` 返回同结构 P50;样本不足返回 null 字段,前端隐藏基准多边形(不假数据)
- **图表**:recharts `<Radar>`,行业基准做第二层半透明多边形叠图(有数据时)
- **交互**:hover 顶点 tooltip 显示 "本期 X% / 行业 Y% / 环比 Δ";点击顶点 → `/brand-growth/matrix?layer=top1|top3|top5|visible|source`,矩阵只染该层级命中
- **后端聚合公式**:对每个 `(query, engine)` cell 取最新 response 的 `brand_rank`,然后 `top1_pct = COUNT(brand_rank=1) / total_cells`,`top3_pct = COUNT(brand_rank<=3)/...`,`visible_pct = COUNT(hit=true)/total`,`source_pct = COUNT(DISTINCT query WHERE hit=true) / total_queries`

## 9. 数据接口清单(修订:no-mock,后端可改)

### 9.1 现状盘点(已有真数据,可直接用)

| 接口 / 字段 | 用途 |
|---|---|
| `GET /topics/:id/overview` | 顶 3 大数(citations.value / owned_split.owned / .other)、可见占比(visibility)、top_domains、engine_domain_matrix、growth、engines_covered |
| `GET /topics/:id/share-of-voice` | SAIV + 段落位置分布 PositionDist(lead/body/tail/unknown,**注意不是 Top1/3/5**) |
| `GET /topics/:id/tracking-matrix` | queries × engines 二值 hit + first_hit_at + hit_cells_pct + timeline |
| `GET /topics/:id/cells/drawer` + `POST cells/insight` | 单格 evidence + 一键洞察 |
| `GET /topics/:id/briefings` + `POST briefings/generate` | 智能洞察 |
| `GET /content/docs?topic_id=&status=published` | 投放战果 |
| `ResponseORM.competitors_json` | LLM 抽取的竞品列表 [{name, count, snippet}] — 现有,可直接做"竞品替代证据" |
| `ResponseORM.citation_domains_json` | 抽取的引用域名列表 — 现有 |
| `ResponseORM.mention_position` | lead / body / tail / unknown(**段落位置**,不是排名) |
| `ResponseORM.answer_format` | listicle / single_recommendation / report / case_study / qa |

### 9.2 必须新增 / 扩展(no-mock 触发的真需求)

| # | 改动 | 用在哪 | 设计 |
|---|---|---|---|
| **1** | `ResponseORM.brand_rank` (新列, Integer, nullable) | 雷达 / Top1/3/5 卡 / 矩阵染色 | 跑批后 LLM 抽取阶段算:在 AI 答案中 brand 第几个被提到(1-based),未命中=NULL。alembic 加列 + 抽取器加字段,无需 mock |
| **2** | `GET /topics/:id/position-breakdown?period=N` | 雷达 5 维 + 右核心指标 4 卡 | 聚:`top1_pct = COUNT(brand_rank=1) / total_cells`,同理 top3 / top5 / visible (=hit_pct) / source_pct (=被引用 query 数 / 总 query 数) |
| **3** | `GET /benchmarks/industry?industry=X` | 雷达底层基准 + 核心指标行业基准小字 | 跨租户聚 `position-breakdown` 的 P50 by industry。最少需要 industry 维度内有 ≥3 个 topic 才算;否则返回 `null` 字段,前端不渲染基准行(不 mock) |
| **4** | `GET /topics/:id/competitor-substitutions?period=N&competitor=X` | C3 竞品分析"被替代证据" | SQL:JOIN responses + query_hits,WHERE `competitors_json LIKE %X%` AND `hit=false`,GROUP BY query。利用现有 `competitors_json` 字段 |
| **5** | `Topic.prompt_extension` (新列, Text) | admin 配置搬迁 | alembic 加列;`runner.py` 跑批组装 prompt 时拼上 |
| **6** | `GET /topics/:id/responses` 加 `?engine=&domain=&date=` query | 信源 / 平台分析的下钻 drawer | 现在按 run 拉,前端 filter 数据量上来会卡;后端加 where clause 即可,~10 行 |
| **7** | `GET /content/docs` 加 `?published_only_with_query_hit=bool` | 战报页"已被 AI 引用 / 未被"筛选 | join `query_hits` on `source_query_text`,boolean 标记 |

> **以上 7 项是 no-mock 上线的硬门槛**。1 / 2 是核心改动(雷达和 Top1/3/5 没它出不来),其它都是 ~50 行级别小改。

### 9.3 字段流详图(brand_rank 是如何产生的)

```
runner.py 跑批
  └─▶ engine 返回 answer + citations
        └─▶ 落 ResponseORM (answer / citations_json)
              └─▶ async LLM 抽取(已有 competitors_json / mention_position 那套)
                    └─▶ 同一抽取里多算一个 brand_rank:
                          prompt: "下面这段 AI 回答中,品牌 {target}(含别名 {aliases})
                                   是第几个被提到的(按出现顺序,1-based)?
                                   如果未提到返回 null。"
                          → UPDATE responses SET brand_rank=?
```

抽取一次 LLM 调用同时拿 mention_position + competitors + brand_rank,**不增加跑批成本**。

普通用户能看到自己的 draft / pending / rejected / approved / published **全状态**,生产 / 审核 / 投放工作流对用户**裸露**。`Content.tsx` 627 行,把"创作 / 审核 / 投放管理"四套 UI 揉在一起。

### 12.3 新版战报页 `/brand-growth/published` 视觉

每条 published 内容渲染成**大卡片**(不是 list row),区别于旧 Content 页的密集表格:

```
┌─────────────────────────────────────────────────────────────────┐
│  [source badge: AI 生成]              published · 2026-05-18    │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━│
│  《一篇正文标题》                                                │
│  正文 summary 摘要文字两行,溢出省略...                          │
│                                                                  │
│  📣 投放到:                                                     │
│   [小红书 ↗] [公众号 ↗] [抖音 ↗]  ← chip 点击开外站 url        │
│                                                                  │
│  ─────────────────────────────────────────────────────────────  │
│  💡 关联查询:"国内 IDC 推荐"  → 看 AI 现在怎么答  →            │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

**卡内字段映射**:
- 标题 + summary → `ContentDoc.title` + `ContentDoc.summary`
- 投放 chips → `publish_targets[].platform` / `.media` / `.url`(链接图标),逐个渲染
- 投放时间 → 取 `publish_targets[*].marked_at` 最早一条,fallback `review_decision_at`
- 来源 badge → `source: 'ai' | 'user'`
- 关联查询 → `source_query_text`,**末尾箭头**链接到 `/brand-growth/queries?q=<source_query_text>`,看这条 query 现在 AI 答案中是否引用了本投放(**ROI 闭环**)
