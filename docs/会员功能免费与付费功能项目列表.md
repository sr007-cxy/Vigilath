## GEO Checker 检测大项一览（25 类）

GEO Checker 默认模式对目标网站执行 **25 类检测**，每一类按子项打分后汇总到 0-100 的 AI Visibility Score，并附字母等级（A+ ~ F）。下表列出每一类的名称、满分占比和检测目标。

> 数据来源：`backend/geo_checker/checks.py` 中 `track_score()` 调用与各 `check_*()` 函数。
> 套餐对应：**匿名访客**仅展示其中的 **5 项基础检测**（下表中标 🆓 的行），**注册会员**及以上解锁全部 25 类完整结果。

| # | 检测大项 | Category Key | 满分 | 匿名可见 | 检测目标 |
|---|---|---|:---:|:---:|---|
| 1 | **HTTPS** | `HTTPS` | 5 | 🆓 | 网站是否启用 HTTPS，HTTP → HTTPS 重定向是否正确配置 |
| 2 | **robots.txt** | `robots.txt` | 8 | 🆓 | robots.txt 存在性、格式合法性，以及对 AI 爬虫（GPTBot / ClaudeBot / PerplexityBot / Google-Extended 等）的允许/拒绝策略 |
| 3 | **llms.txt** | `llms.txt` | 5 | | 是否提供 `llms.txt` 文件，为 LLM 提供结构化的内容索引与抓取指引 |
| 4 | **.well-known** | `.well-known Discovery` | 3 | | `/.well-known/` 路径下的标准发现文件(如 `ai.txt`、`security.txt`)是否齐备 |
| 5 | **Sitemap** | `sitemap.xml` | 7 | 🆓 | `sitemap.xml` 是否存在、是否有效、是否在 robots.txt 中正确声明，URL 数量是否合理 |
| 6 | **Platform Registration** | `Search Engine & AI Platform Registration` | 7 | | 在主流搜索引擎与 AI 平台的注册与收录情况(Google / Bing / 百度 等) |
| 7 | **Structured Data** | `Structured Data` | 7 | | JSON-LD 结构化数据的存在性、schema.org 类型多样性与有效性 |
| 8 | **Meta Tags** | `Meta Tags` | 7 | 🆓 | 关键 meta 标签的完整性：`title`、`description`、`og:*`、`twitter:*`、canonical 等 |
| 9 | **Content Accessibility** | `Content Accessibility` | 6 | | 内容是否对爬虫可读，是否被 JavaScript 渲染、登录墙、付费墙阻挡 |
| 10 | **AI Crawl Readiness** | `AI Crawl Readiness` | 8 | | 整体 AI 爬虫可访问性、对 AI User-Agent 的响应行为是否友好 |
| 11 | **Content Quality** | `Content Quality for AI` | 7 | | 内容长度、段落结构、标题层级、可引用性 |
| 12 | **Technical Crawlability** | `Technical Crawlability` | 5 | | HTTP 响应码、重定向链长度、跳转层数、错误页面处理 |
| 13 | **Authority & Trust** | `Authority & Trust` | 5 | | 站点权威信号：域名年龄、外链证据、可信元素(联系方式、隐私政策等) |
| 14 | **Brand Entity KG** | `Brand Entity KG` | 5 | | 品牌实体在知识图谱中的存在与关联度（Wikipedia / Wikidata / Google KG） |
| 15 | **Trust & Safety** | `Trust & Safety` | 6 | | 网站信任与安全信号：隐私政策、服务条款、安全认证、联系信息完整性等 |
| 16 | **AI Optimization** | `AI-Specific Optimization` | 5 | | 针对 AI 引擎的特定优化：FAQ、How-To 块、答案式内容结构 |
| 17 | **Social Signals** | `Social Signals` | 3 | | 社交媒体链接的存在性、JSON-LD `sameAs` 字段的覆盖度 |
| 18 | **AI Answer Formats** | `AI Answer Format Optimization` | 5 | | 内容是否以 AI 易抽取的格式呈现：Q&A、表格、列表、定义块 |
| 19 | **Schema & Knowledge** | `Schema Breadcrumbs & Knowledge Panel` | 4 | | 与知识图谱的关联：Wikipedia、Wikidata、Google Knowledge Panel 等的覆盖 |
| 20 | **Mobile & Weight** | `Mobile-Friendliness & Page Weight` | 4 | 🆓 | 移动端友好性(viewport、响应式) + 页面体积(HTML 大小、首屏字节数) |
| 21 | **URL Normalization** | `URL Normalization` | 2 | | URL 规范化：canonical 标签、trailing slash 一致性、参数处理 |

## 权限控制技术实现

### 检测分类过滤

| 层级 | 端点 | 可见分类 | 实现 |
|---|---|---|---|
| 匿名 | `POST /check/anonymous` | 5 项 (`FREE_CHECK_CATEGORIES`) | `_strip_locked_checks()` 移除非 free 分类 |
| 注册+ | `POST /check` | 25 项（`allowed_check_categories = None` 表示全部） | `_locked_for()` 返回空列表 |

### Fix 优化建议门控

- 后端 `_FIX_ALLOWED_TIERS = frozenset({"starter", "growth", "scale"})`
- Free / Pro 用户的 `include_fix` 参数被强制设为 `False`，Fix 文本永远不离开后端

### 配额执行

| 用户类型 | 配额 | 追踪方式 |
|---|---|---|
| 匿名 | 3 次/月 | `AnonymousCheckUsageORM`，按 `geo_anon_id` Cookie + `year_month` |
| 注册 Free | 3 次/月 | `UserCheckUsageORM`，按 `user_id` + `year_month` |
| Pro | 20 次/月 | 同上，`monthly_check_quota = 20` |
| Starter / Growth / Scale | 无限 | `monthly_check_quota = 0`（0 = 无限） |

### 评分计算说明

所有 25 类检测**始终全部执行**，不论用户等级。评分（0-100 AI Visibility Score + 字母等级）反映网站的真实 GEO 状态。低等级用户只是**看不到**被锁定分类的详细检查结果，但总分不会因此虚高。这确保了：
- 即使匿名用户也能看到真实分数
- 付费动机（低分但无法看到具体哪些项需要改进）
- 深拷贝结果避免缓存跨等级污染
