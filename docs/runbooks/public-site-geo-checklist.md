# Public Site GEO Checklist

Owner: frontend and public-site operations
Last reviewed: 2026-08-28

## Canonical identity

- Brand: Vigilath
- Positioning: Unified GEO+AEO for Global AI Visibility
- Primary hostname: `www.vigilath.com`
- Support contact: `support@zen7.com`

## Change checklist

- [ ] Organization name and product description agree across visible pages.
- [ ] Canonical URLs use the primary HTTPS hostname.
- [ ] Support and legal contact details are consistent.
- [ ] `robots.txt`, `sitemap.xml`, `llms.txt`, and
      `/.well-known/` files are present in the production artifact.
- [ ] Sitemap URLs resolve without redirect chains or mixed hostnames.
- [ ] Structured metadata uses the same organization, product, and canonical
      identity as visible content.
- [ ] Route-specific title, description, canonical URL, and crawlable fallback
      content are generated by the production build.
- [ ] No private hostnames, credentials, customer data, or internal deployment
      details appear in public discovery files.
- [ ] The public URL audit is rerun after deployment and its timestamp is
      recorded in the release note.

## Repository locations

- Discovery files: `frontend/public/`
- Route-specific SEO generation: `frontend/vite.config.ts`
- Public copy and translations: `frontend/src/i18n/`
- nginx deployment behavior: `frontend/nginx.conf` and `backend/deploy/`

## Verification

```bash
cd frontend
npm run build
test -f dist/robots.txt
test -f dist/sitemap.xml
test -f dist/llms.txt
```

After publishing, verify the production hostname directly rather than relying on
the local build alone.
