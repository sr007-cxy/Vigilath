## 0. 一句话结论

讯灵是一套「**蒸馏 → 内容投放 → AI 引擎检测**」三段闭环的国产 GEO 代运营 SaaS,挂在火山引擎合作伙伴体系上,核心壁垒不是扩词技术,而是 5 类媒体的**真实发布席位**和 12 cell × 6 国产 AI 引擎的真浏览器 probe 网络。**14 万条蒸馏长尾既是内容生成素材也是 probe 池源头,两条链路同源**。

## 1. 平台与架构

- **公开形态**:Vue 单页,hash 路由(`/#/geo/*`),登录页是首页 + 弹窗
- **底层接的是抖音SEO 老平台**:API 网关分布在 `/dyseo/`(主)、`/qyt/`(用户/订阅)、`/bdk/`(视频)、`/yzt/`(AI 搜索词管理)、`/zl/aiSearchRanking/`(成绩单)、`/yzt/api/aisearch/aiwash/`(AI 答案清洗)
- **认证机制**:浏览器登录后服务端发 `token` header(URL-encoded base64),前端逐请求带上;无标准 OAuth,无 cookie 全局会话

## 3. AI画像页的真实数据结构

UI 上看是「训练词表」(序号/训练词/蒸馏词数量/场景/时间/训练次数/操作),但**真实数据模型有 4 层**:

```
画像(brand entity,需实名认证 + 抖音授权才能创建)
  │
  ├─ 训练词(seed,4 类场景之一)   ← API 字段 name
  │     │
  │     └─ 蒸馏内容(content[],LLM 一次性扩展)   ← API 字段 content
  │           │
  │           └─ 100~150 条长尾(基于固定模板)
  │
  └─ 素材(图片/视频/资料)   ← 上传/引用素材库
```

**5 个顶部 Action**(都需要 `立即认证 + 前往授权` 落地):

| Action | 实际语义 |
|---|---|
| 添加画像 | 建 brand 主体(勾选《信息安全协议》) |
| 添加场景 | 二级菜单,选 4 类场景之一,进添加训练词流程 |
| 添加图片/视频/资料 | 给画像挂素材 |

**添加场景弹窗内 3 种录入方式**:

- **批量添加** — 用户粘贴一列种子词
- **拓词** — LLM 自动同义扩展(把 1 个 seed 变 N 个 seed)
- **数据挖掘** — 用搜索数据反推热门长尾

## 4. 4 个场景类型(语义与实例)

每个场景**对应不同的训练词形态**,蒸馏后用同一套模板词典生成长尾。测试账号实测数据:

| 场景 | 训练词形态 | 训练词数 | 蒸馏长尾形态 |
|---|---|---:|---|
| **搜索词场景** | 品类/产品**关键词**(裸词) | 1,838 | `XX厂家 / XX供应商 / 推荐XX厂家 / 高性价比的XX` 等 SEO 长尾 |
| **问答词场景** | 带推荐意图的**短语** | 195 | `XX怎么样 / XX哪家好 / XX 排名` 等问答词 |
| **意图场景** | 用户**意图短语**(怎么选/如何) | 178 | 短语本身已是长尾,蒸馏量少;部分入库是**图片 URL**(挂素材) |
| **品牌场景** | 品牌词 | (与 type4 编码不一致,见数据备注) | `品牌+介绍/详细介绍/基本信息/公司概况/客户评价` 等品牌长尾 |

**实例(seed → 长尾节选)**:

品牌场景(同一品牌可加多个 seed,扩展不同业务线):

## 5. 三个数据池及其关系(本次调研最大修正)

> 这是反复迭代后的最终结论 —— 前 3 轮我误判过两次,这是实测交叉验证后的版本。

### 三个池

| 池 | 数量 | 字段 | 用途 |
|---|---:|---|---|
| **训练词种子** | 2,211 unique(搜索/问答/意图三类合计;UI 显示 1838 是含合并的种子计) | `name` | 用户录入的 seed,挂在画像下 |
| **蒸馏长尾池** | **142,458** unique | `content[]` | seed × LLM 模板 → 100~150 长尾/seed |
| **推荐词池** | 103 unique(769 cell 实例) | `keyword` | 长尾经"问题化变形"后喂 AI 引擎 probe |

### 三池之间的关系(实测验证)

```
seed (e.g. "南方网通")
   ↓ 蒸馏(LLM 用 ~10 个固定模板:怎么样/介绍/详细介绍/基本信息/
                                  公司概况/实力/性价比/客户评价/团队/概况)
长尾池 (142,458 条 = 2,211 seeds × ~64 长尾/条)
   ├──🅰 内容生成 → 备课 → 文章 → 授课发布
   └──🅱 问题化变形(加地域前缀"顺德/中山",加关联实体,微调句式)
        ↓
     推荐词池 (103 unique × 12 engine cell ≈ 769)
        ↓
     真浏览器跑 AI 引擎 probe → 落 cell
```

| 模板词 | 长尾池命中 | 推荐词池命中 |
|---|---:|---:|
| 怎么样 | 4,309 | 10 |
| 实力 | 6,694 | 9 |
| 性价比 | 3,661 | 6 |
| 介绍 | 1,338 | 6 |

| 推荐词 | 长尾池最近邻 | 相似度 |

## 6. 检测机制(probe)详解

### probe 一条 record 的完整 schema(API 实采)

```jsonc
{
  "rid": 20769,
  "uid": 50055200,
  "domain": "sohu.com",                       // 信源(citation URL 所在 domain)
  "keyword": "顺德南方网通的团队实力如何",     // 推荐词 = 喂 AI 的 probe
  "queries": "顺德南方网通的团队实力,顺德南方网通介绍",  // AI 内部抽取的子 query
  "title": "南方网通:专业抖音推广运营团队，揭秘收费标准_企业_平台_品牌",
                                              // AI 答案 citation 命中的文章标题
  "mtime": 1754182972,                        // probe 时间
  "type": "doubao",                           // 哪个引擎
  "taskId": 306, "taskType": 1,
  "subject": "抖音推广",                       // probe 关联的业务主题
  "wordCount": 13, "subjectCount": 4
}
```

### 实际操作流程(从字段 + 结构反推)

```
推荐词 ("顺德南方网通的团队实力如何")
  ↓ 真浏览器开 豆包PC 网页 / 豆包 App
  ↓ 把推荐词作为用户提问发进去
  ↓ AI 返回答案 + citations
  ↓ 系统解析:
    - keyword       = 提问原文
    - queries       = AI 答案里展开的 sub-query(用于二次匹配)
    - title/domain  = 答案 citation 命中的文章
    - subject       = 关联业务主题(用于成绩单聚合)
  ↓ 落 cell (品牌, 推荐词, 引擎×端, 命中位置, citation)
  ↓ 聚合 → Top1 / Top3 / Top5 / 可见占比 / 信源占比
```

### 测试账号实测 cell 分布(总览栏)

| 引擎 | PC | 手机 | 小计 |
|---|---:|---:|---:|
| 豆包 | 29 | 28 | 57 |
| DeepSeek | 73 | 69 | 142 |
| 文心一言 | 73 | 72 | 145 |
| 元宝 | 72 | 70 | 142 |
| 千问 | 72 | 70 | 142 |
| 纳米 | 71 | 70 | 141 |
| Kimi | 0 | 0 | 0 |
| **合计** | | | **769** |

豆包数明显偏低 = 字节系限流。"信源占比"指标的 domain 字段几乎全是 `sohu.com` —— 表明发布渠道集中在搜狐号。

### 5 个核心指标(成绩单 > 核心指标表现)

- **Top1占比** — 答案首条命中本品牌占比
- **Top3占比 / Top5占比** — 排进前 3/5 占比
- **可见占比** — 答案文本任意位置被提及占比
- **信源占比** — 答案 citation 命中我方发布文章占比(双闭环的关键)

## 7. 对比本仓库 GEO 项目

> 本仓库(`backend/geo/`)的 `expand_queries_for_topic` + `content_generator` + `citation_match` 构成一个对应链路。

| 维度 | 讯灵 | 本仓库 GEO |
|---|---|---|
| **数据资产** | 1 brand → 多 seed → 14 万长尾 | 1 topic → seed_prompts_json → ≤200 query 候选 → ≤50 selected |
| **种子来源** | 用户加 seed,系统帮拓词/数据挖掘 | 用户提 seed prompt,LLM 扩展(deepseek 默认) |
| **扩展量级** | 100-150 长尾/seed,无限扩 | 5-200 query/seed(MAX_EXPANSION_CANDIDATES=200) |
| **扩展词去向** | 同一池子:🅰 内容生成 🅱 probe(同源不同终点) | 同一池子:run on engines + content_generator |
| **probe 与文章共用扩展词?** | ✅ 同源(模板重合,推荐词 = 长尾 + 微变形) | ✅ 同源(selected_queries 既 run 又 generate) |
| **probe 引擎** | 6 国产 × PC/手机 真浏览器 | Perplexity / OpenRouter / 自研 telemetry-service |
| **probe 信号** | Top1/3/5 + 可见 + 信源占比 4 维 | citation_match(citation URL ↔ 投放 doc URL) |
| **内容发布** | **真发布**(可发条数=席位,按 16 条/期扣费) | **标注式**(`publish_targets_json` 注释:不真实调外部 API) |
| **媒体渠道** | 5 类媒体席位(搜狐号等),按 sohu.com 集中 | 公众号/小红书/抖音/视频号 文案生成,运营自发 |
| **场景维度** | 4 类场景(搜索/问答/意图/品牌),每类独立 seed 库 | 单一(不分场景,所有 query 一锅) |
| **品牌主体** | 画像(实名认证 + 抖音授权) | Topic(用户层级,无认证) |
| **数据看板** | 成绩单(趋势/信源/平台/竞品/视频/智能体/关键词 7 tab) | brand-growth/{sources,engines,competitors,matrix,insights,queries,responses,published} |
| **诊断前置** | 几乎没有,直接录 seed 就开训 | 重:6 步 stepper(画像 → 诊断 → 方案 → 计划 → 文案 → 监控) |
| **独有模块** | 智能体名片/官网(独立 AI 数字员工页) | 舆情、GEO Readiness Checker(25 维 0-100) |
| **计费** | 可发条数配额 + 到期日 | membership 套餐 + topic usage |

## 8. 商业模型解读

### 讯灵的护城河不在算法

- **扩词 / 蒸馏**:就是用 ~10 个模板词的 LLM 调用,任何家都能复现
- **probe**:真浏览器自动化(类似本仓库 `backend/browser_engine/`),工程量大但非黑科技
- **真正的壁垒是** 5 类媒体的**真实发布渠道**(搜狐号 / 行业自媒体白名单 / 视频号矩阵)和**抖音/字节系数据回填**(uid 50055200 这种老账号在抖音SEO 后台有历史数据)

### 计费形态

按"**可发条数 × 媒体类型**"卖席位(测试账号 16 条第三方新闻可发到 2026-07-22),不卖工具用量(蒸馏/probe 不单独计费,被打包进席位)。

### 闭环依据

- 备课/授课 把"我方文章"投到 sohu.com 等媒体 → 这些文章被 AI 引擎抓为信源
- probe 看 AI 答案 citation 是否命中我方文章 → **信源占比**指标
- 客户看到 Top1/3/5 占比涨,愿意续约更多可发条数
