# GEO Readiness Checker — 付费解锁与权限控制需求文档

> **权威源**：[`会员功能免费与付费功能项目列表.md`](./会员功能免费与付费功能项目列表.md) 定义的 **5 档套餐**是本文档的唯一权威档位来源。如有冲突以会员档位文档为准。
>
> 本文档是 `需求文档-付费解锁` 与原 `权限控制方案` 的**合并版本**。前半部分（§1–§6）是付费墙 UX 需求；后半部分（§7–§13）是完整的后端权限控制策略。两者共用同一套 5 档结构。

---

## 1. 背景

GEO Readiness Checker 是一款网站 GEO（Generative Engine Optimization）就绪度检测工具。为驱动会员转化并构建可持续的商业模式，需要在检测结果页和其他高级检测功能中引入付费墙（Paywall）机制，同时建立严谨的后端权限控制体系。

## 2. 当前问题

1. **结果页无付费引导**（UX 问题）：`Result.tsx` 对所有用户展示全部检测结果，缺乏付费动机。
2. **登录态判断失效**（已修复）：原代码通过从未赋值的 `user` state 判断登录，实际永远为未登录。已通过 `hooks/useMembership.ts` 统一修复。
3. **会员升级入口单一**（UX 问题）：目前只有用户主动进入 `/membership` 页面才会触发升级流程。
4. **高级检测功能无付费闸门**（后端问题）：CLI 的 `--crawl-test` / `--authority-audit` / `--citation-check` / `--ai-visibility` / `--entity` 等付费模式，前端尚未按会员等级做访问控制，后端也未做身份校验。
5. **Tabs 切换是按钮样式，非真正的 tabs**（UX 问题）：需要做专业的 tabs 展示。
6. **后端几乎没有权限控制**：`POST /api/geo`、`GET /api/geo/stream` **完全匿名可调**，无配额、无限流、无档位校验。`SECRET_KEY` 硬编码为占位符。
7. **前端免费规则与权威档位不一致** ⚠️：当前 `Result.tsx` 用 `FREE_CHECKS_PER_TAB = 2`（每分类前 2 项），但会员档位文档定义的免费范围是**固定 5 项**（HTTPS / robots.txt / Sitemap / Meta Tags / Mobile & Weight）。需在本次重构中统一为固定 5 项。

## 3. 目标

- 让未登录/免费用户只能看到权威档位定义的 **固定 5 项基础检测结果**，激发付费意愿。
- 让注册流程自然过渡到付费流程，提高付费转化率。
- 对高级检测功能实施后端强校验的订阅门槛，保障付费用户权益。
- 所有付费引导均保持良好的用户体验，不得阻塞核心免费功能。
- **建立完整的后端权限控制体系**：身份认证、授权、配额、限流。

## 5. 免费用户的可见范围规则（权威）

### 5.1 固定 5 项基础检测

**未登录访客** 与 **免费会员** 可以看到的检测结果**固定为以下 5 项**，不按"每分类前 2 项"的方式分配：

| # | 检测大项 | 满分 |
|---|---|:---:|
| 1 | HTTPS | 5 |
| 2 | robots.txt | 8 |
| 3 | Sitemap | 7 |
| 4 | Meta Tags | 7 |
| 5 | Mobile & Weight | 4 |
| | **合计** | **31** |

其余 18 类（llms.txt、.well-known、Platform Registration、Structured Data、Content Accessibility 等）对免费用户**全部锁定**。

### 5.2 为什么是"固定 5 项"而非"每类前 2 项"

- **权威源一致性**：会员档位文档第 7 节已明确定义这 5 项，且整条营销阶梯都围绕这 5 项展开
- **可解释性**：销售文案能直接说"我们免费帮你检测 17 个具体维度（对应 5 项 31 分）"，比"每大类前 2 个"更清晰
- **覆盖基本面**：HTTPS + robots.txt + Sitemap + Meta Tags + Mobile & Weight 恰好覆盖"安全 / 抓取规范 / 可发现性 / 元数据 / 体验"五大基本面
- **降低滥用价值**：免费能看到的所有项目都是"表层硬指标"，不泄露深度分析价值

### 5.3 总分与摘要的可见性

- **AI Visibility 总分、等级、分类摘要**（通过 / 警告 / 失败 / 信息数量）对所有用户可见
- 总分按**全量 23 类**计算后归一化为 0-100（不因免费用户只看 5 项就只算 5 项的分数），避免用户看到的分数和后台处理的分数不一致

### 5.4 锁定态的 UI 呈现

- 锁定卡片以**虚线边框 + 锁图标 + 占位骨架条**呈现，不泄露具体内容
- 点击锁定卡片或"查看更多"按钮触发解锁流程（见 §6.2）
- 锁定数量达到阈值后显示统一的升级 CTA 区域

## 6. 功能需求（付费墙 UX）

### 6.1 结果页分类与锁定展示（F-1）

**F-1.1 Tab 分类结构**

结果页按 **4-5 个 Tab** 展示 23 类检测项：

- **网站基础**：HTTPS、robots.txt、Sitemap、URL 规范化
- **AI 优化**：llms.txt、AI 爬取就绪度、AI 优化、AI 回答格式
- **内容质量**：可访问性、内容质量、Meta 标签、结构化数据
- **技术性能**：技术可抓取性、移动与体积、.well-known
- **外部因素**：权威与信任、社交信号、跨平台、Platform Registration、Multi-Page、Multilingual、Outbound & Media、Schema & Knowledge

**F-1.2 Tab 样式**

必须是**专业的 tabs 控件**（非按钮组）：
- 活动 tab：底部霓虹下划线 + 文字高亮
- 非活动 tab：灰文字，hover 时高亮
- 切换时有平滑过渡动画

**F-1.3 免费预览规则（按 §5 对齐）**

- **未登录** 与 **免费会员**：在每个 tab 内只解锁属于固定 5 项白名单的检测项，其余均为锁定卡片
  - 例：「网站基础」tab 下，HTTPS / robots.txt / Sitemap 解锁，URL 规范化 锁定
  - 例：「技术性能」tab 下，Mobile & Weight 解锁，技术可抓取性 / .well-known 锁定
- **已付费会员**（`pro` 及以上）：展示全部 23 类检测项

**F-1.4 锁定卡片交互**

- 点击锁定卡片 → 触发解锁流程（见 §6.2）
- 每个 tab 在锁定卡片之后显示一个高亮的解锁 CTA 区域，包含说明文案与"查看更多"按钮

### 6.2 解锁与付费流程（F-2）

**F-2.1 未登录点击解锁**

- 跳转至 `/login` 页面，登录页提供注册入口

**F-2.2 已登录但未付费点击解锁**

- 弹出 `PaymentModal` 支付弹窗，用户在弹窗内选择套餐并完成升级
- 支付成功后：关闭弹窗，页面刷新 token 状态，自动展示全部检测项
- 用户可点击「暂时跳过」关闭弹窗，返回继续浏览锁定状态的结果

**F-2.3 注册后自动付费引导**

- 用户完成注册后，前端立即调用登录接口获取 token 并存入 `localStorage`
- 自动弹出 `PaymentModal` 支付弹窗，引导用户选择套餐
- 支付成功 → 跳转 `/membership` 展示会员状态
- 跳过支付 → 跳转 `/` 首页（用户此时已登录，但仍为免费会员）

## 7. 权限控制策略（合并自原权限控制方案）

### 7.1 设计原则

| 原则 | 说明 |
|---|---|
| **最小权限** | 默认拒绝，显式允许 |
| **按档位分级** | 用户能做什么由其会员档位决定，避免散落 if-else |
| **失败明确** | 4xx 错误必须给出可操作信息（配额数、升级档位） |
| **匿名优先** | 免费会员无需注册即可使用，但通过 IP 限流防滥用 |
| **权威源单一** | 档位、配额、检测项清单全部从会员档位文档引用 |
| **YAGNI** | 不引入当前用不到的抽象（如 RBAC 角色表） |

### 7.2 身份层级

系统识别 **5 种身份**（按权限递增）：

| # | 身份 | 识别方式 |
|---|---|---|
| 1 | **匿名访客** | 无 Token，按客户端 IP 哈希追踪 |
| 2 | **免费会员** | JWT Token + `membership.slug = 'free'` |
| 3 | **检测会员** | JWT Token + `membership.slug = 'pro'` |
| 4 | **人工服务客户** | JWT Token + `membership.slug ∈ {'starter','growth','scale'}` |
| 5 | **管理员** | JWT Token + `users.is_admin = TRUE` |

> 身份 1（匿名）和身份 2（免费会员）在**检测能力上等价**（都只能看固定 5 项结果），区别仅在于配额来源（匿名按 IP，免费会员按 user_id）。

## 9. 身份认证机制

### 9.1 JWT Bearer（已有，需改进）

| 项 | 现状 | 目标 |
|---|---|---|
| Token 类型 | JWT（HS256） | 不变 |
| Token 载荷 | `{sub: email, exp}` | 增加 `mid` (membership_id) 和 `tier` (slug)，减少每次查库 |
| 过期时间 | 30 分钟 | **延长至 24 小时** |
| Refresh Token | ❌ 无 | ❌ **暂不实现**（Token 过期重新登录即可） |
| `SECRET_KEY` | ⚠️ 硬编码 `"your-secret-key-here"` | **从环境变量读取**，启动时校验非空 |
| 密码哈希 | bcrypt | 不变 |

### 9.2 FastAPI Dependency 层级

```
get_optional_user()    → 返回 User or None（可选登录）
get_current_user()     → 返回 User（必须登录），未登录返回 401
require_tier(tiers)    → 要求 user.membership.slug ∈ tiers，不符返回 403
require_admin()        → 要求 user.is_admin，不符返回 403
check_quota()          → 检查配额，超额返回 429
```

### 9.3 端点组合示例

```python
@router.post("/api/check")
async def run_check(
    request: CheckRequest,
    user: User = Depends(get_current_user),
    quota: Quota = Depends(check_quota),
):
    ...

@router.post("/api/check/ai-visibility")
async def ai_visibility(
    request: AIVisibilityRequest,
    user: User = Depends(require_tier(["pro", "starter", "growth", "scale"])),
    quota: Quota = Depends(check_quota),
):
    ...
```

## 10. 检测项分级控制

### 10.1 分级规则（权威）

| 身份 | 运行的检测项 | 可见结果数 | 满分 |
|---|---|---|:---:|
| 匿名 / 免费会员 | 后端跑全量 23 项，前端只展示 5 项白名单 | **5 项** | 31 |
| 检测会员 及以上 | 全量 23 项 | **23 项** | 118 |

### 10.2 实施位置：SaaS 服务层

**决策**：`geo_checker.py` 保持现状（始终跑全量 23 类）。SaaS 服务层在返回结果前按 `allowed_check_categories` 字段**过滤结果**。

**理由**：
- CLI 开发者体验不变
- 修改单点，未来若调整免费白名单不用动 `geo_checker.py`
- 避免 `geo_checker.py` 引入 tier 概念导致职责混乱

**代价**：过滤会浪费约 74% 的计算（23 项跑完只返 5 项），可接受。

### 10.3 `memberships` 表扩展字段

```sql
ALTER TABLE memberships ADD COLUMN slug TEXT UNIQUE;
ALTER TABLE memberships ADD COLUMN monthly_check_quota INTEGER NOT NULL DEFAULT 0;
ALTER TABLE memberships ADD COLUMN allowed_check_categories TEXT;
-- JSON array, e.g. '["HTTPS","robots.txt","Sitemap","Meta Tags","Mobile & Weight"]'
-- NULL = 全部 23 项
ALTER TABLE memberships ADD COLUMN tier_type TEXT DEFAULT 'saas';
```

### 10.4 过滤函数伪代码

```python
def filter_result_by_tier(result: GeoResult, allowed: Optional[List[str]]) -> GeoResult:
    if allowed is None:
        return result   # 全部返回
    filtered = [c for c in result.categories if c.name in allowed]
    return GeoResult(
        url=result.url,
        score=result.score,   # 总分保持全量计算，不因过滤而变化
        categories=filtered,
        tier_hint={"locked": len(result.categories) - len(filtered)}
    )
```

### 10.5 前端锁定占位

前端收到 `tier_hint.locked = 18` 时，在 18 个非白名单位置渲染锁定卡片（见 §6.1.4）。

## 11. 配额策略

### 11.1 DB Schema

**`user_check_usage` 表**（已登录用户）：

```sql
CREATE TABLE user_check_usage (
  user_id     INTEGER NOT NULL,
  year_month  TEXT NOT NULL,       -- 'YYYY-MM'
  used_count  INTEGER DEFAULT 0,
  updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (user_id, year_month),
  FOREIGN KEY (user_id) REFERENCES users(id)
);
```

**`anonymous_check_usage` 表**（匿名用户）：

```sql
CREATE TABLE anonymous_check_usage (
  ip_hash     TEXT NOT NULL,       -- SHA256(ip + daily_salt)，不存原 IP
  year_month  TEXT NOT NULL,
  used_count  INTEGER DEFAULT 0,
  updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (ip_hash, year_month)
);
```

### 11.2 配额周期

**按自然月分桶**（`YYYY-MM`）：

- 4 月 1 日 00:00 起用户自动拥有新的 4 月配额（无需定时清零）
- 历史月数据保留 12 个月后归档

### 11.3 中间件伪代码

```python
async def check_quota(
    request: Request,
    user: Optional[User] = Depends(get_optional_user),
):
    year_month = datetime.utcnow().strftime("%Y-%m")
    tier = user.membership.slug if user else "anonymous"
    quota = QUOTA_MAP[tier]

    if quota == 0:   # 无限
        return

    if user:
        used = get_user_used(user.id, year_month)
    else:
        ip_hash = hash_ip(request.client.host)
        used = get_anonymous_used(ip_hash, year_month)

    if used >= quota:
        raise HTTPException(
            status_code=429,
            detail={
                "error": "quota_exceeded",
                "message": f"Monthly quota of {quota} reached",
                "tier": tier,
                "used": used,
                "limit": quota,
                "reset_at": next_month_first_day(),
                "upgrade_url": "/products-services"
            }
        )
```

### 11.4 超额响应格式（429）

```json
{
  "error": "quota_exceeded",
  "message": "Monthly quota of 3 reached",
  "tier": "free",
  "used": 3,
  "limit": 3,
  "reset_at": "2026-05-01T00:00:00Z",
  "upgrade_url": "/products-services"
}
```

## 12. 匿名限流策略

### 12.1 IP 哈希（隐私保护）

- **不存原始 IP**，存 `SHA256(ip + daily_rotating_salt)`
- `daily_rotating_salt` 从环境变量读取
- 合规：规避 GDPR / PIPL 对原始 IP 存储的要求

### 12.2 提取客户端 IP（优先级）

1. `X-Forwarded-For` 第一个
2. `X-Real-IP`
3. `request.client.host`

### 12.3 防 VPN 绕过

**第一阶段不做**，观察滥用情况。

**防御性预案**：
- 接入 Cloudflare Turnstile 或 reCAPTCHA v3
- 匿名配额从 3 次/月降到 1 次/月
- 按 IP 段（/24）做周级限流

### 12.4 豁免名单

- `127.0.0.1` / `localhost` 豁免（本地开发）
- 运维 IP 白名单（可选）

## 14. 错误码规范

| HTTP 状态 | error 字段 | 使用场景 |
|---|---|---|
| **400** | `invalid_input` | URL 格式错误、参数缺失 |
| **401** | `unauthenticated` | 无 Token / Token 过期 / Token 无效 |
| **403** | `forbidden` | 有 Token 但无权限（如非管理员访问管理员端点） |
| **403** | `ownership_mismatch` | 试图修改别人的资源 |
| **403** | `tier_required` | 档位不足（如 `free` 访问 `/api/check/ai-visibility`） |
| **404** | `not_found` | 资源不存在 |
| **409** | `conflict` | 重复注册、重复订阅 |
| **429** | `quota_exceeded` | 月度配额用尽（主要场景） |
| **429** | `rate_limit_exceeded` | 短时间高频请求（未来 rate limiter 启用后） |
| **500** | `internal_error` | 未捕获异常 |

### 14.1 前端对 401/403/429 的区别处理

- **401** → 跳转登录页
- **403 tier_required** → 弹 `PaymentModal` 引导升级
- **403 forbidden** → 显示"权限不足"提示
- **429 quota_exceeded** → 显示"本月配额已用完" + upgrade_url 跳转

## 15. 业务规则

- **R-1** 免费用户可见范围 = 权威的 5 项白名单，不使用"每分类前 N 项"策略。`FREE_CHECKS_PER_TAB = 2` 常量应废弃
- **R-2** 登录态判断以 `localStorage.token` + 后端 `/api/user-membership` 的 `is_active` 字段为唯一真相源
- **R-3** 过期会员视为免费用户
- **R-4** 支付弹窗仅展示价格 > 0 的付费套餐（隐藏免费套餐）
- **R-5** 所有付费功能必须**前端 + 后端双重校验**，前端只做 UX 引导
- **R-6** 免费用户保留的 5 项基础检测必须完整可用，不得退化
- **R-7** 总分按全量 23 类计算，不因用户只看 5 项而重新归一化
- **R-8** 人工服务档位（`starter` / `growth` / `scale`）的权益差异**不在检测能力**，而在人工服务维度（见会员档位文档 §4）
- **R-9** `SECRET_KEY` 必须从环境变量读取，生产环境禁止硬编码
- **R-10** 匿名限流按 IP 哈希实施，不存储原始 IP
