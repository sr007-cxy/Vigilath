# GEO Readiness Checker — 付费解锁需求文档

## 1. 背景

GEO Readiness Checker 是一款网站 GEO（Generative Engine Optimization）就绪度检测工具。当前产品已支持免费网站检测、结果展示、会员体系（免费版 / 基础 / 高级 / 企业）。为驱动会员转化并构建可持续的商业模式，需要在检测结果页和其他高级检测功能中引入付费墙（Paywall）机制。

## 2. 当前问题

1. **结果页无付费引导**：Result 页面对所有用户展示全部检测结果,未登录与付费用户体验一致,缺乏付费动机。
2. **登录态判断失效**：`Result.tsx` 中的登录态通过一个从未被赋值的 `user` state 判断,实际永远为未登录,但所有检测项依然展示。
3. **会员升级入口单一**：目前只有用户主动进入 `/membership` 页面才会触发升级流程,注册后没有自然的付费引导。
4. **其他高级检测方式缺乏付费闸门**:CLI 支持 `--crawl-test`、`--authority-audit`、`--citation-check`、`--ai-visibility`、`--entity` 等付费检测模式,但前端尚未按会员等级进行访问控制。
5. tabs 切换是按钮，不是 tabs 样式，请完成专业的 tabs 展示

## 3. 目标

- 让未登录/免费用户只能预览部分结果,激发付费意愿。
- 让注册流程自然过渡到付费流程,提高付费转化率。
- 对高级检测功能实施订阅门槛,保障付费用户权益。
- 所有付费引导均保持良好的用户体验,不得阻塞核心免费功能。

## 4. 功能需求

### 4.1 结果页分类与部分展示

**F-1.1 分类结构**

- 结果页按 **4-5 个大类** 展示检测项,当前分类定义为:
  - 网站基础(HTTPS、robots.txt、Sitemap、URL 规范化)
  - AI 优化(llms.txt、AI 爬取就绪度、AI 优化、AI 回答格式)
  - 内容质量(可访问性、内容质量、Meta 标签、结构化数据)
  - 技术性能(技术可抓取性、移动与体积、.well-known)
  - 外部因素(权威与信任、社交信号、跨平台)

**F-1.2 免费预览规则**

- **未登录用户** 与 **免费会员**:每个大类**仅展示前 2 个检测项**,其余项以"锁定卡片"占位。
- **已登录且已付费会员**:展示分类下的全部检测项。
- 总分、分类摘要(通过/警告/失败/信息数量)对所有用户可见,不受锁定限制。

**F-1.3 锁定卡片交互**

- 锁定卡片以**虚线边框 + 锁图标 + 占位骨架条**呈现,不泄露具体内容。
- 点击锁定卡片或"查看更多"按钮触发解锁流程(见 4.2)。
- 每个大类在锁定卡片之后显示一个高亮的解锁 CTA 区域,包含说明文案与"查看更多"按钮。

### 4.2 解锁与付费流程

**F-2.1 未登录点击解锁**

- 跳转至 `/login` 页面,登录页提供注册入口。

**F-2.2 已登录但未付费点击解锁**

- 弹出 `PaymentModal` 支付弹窗,用户在弹窗内选择套餐并完成升级。
- 支付成功后:关闭弹窗,页面刷新 token 状态,自动展示全部检测项。
- 用户可点击"暂时跳过"关闭弹窗,返回继续浏览锁定状态的结果。

**F-2.3 注册后自动付费引导**

- 用户完成注册后,前端立即调用登录接口获取 token 并存入 `localStorage`。
- 自动弹出 `PaymentModal` 支付弹窗,引导用户选择套餐。
- 支付成功 → 跳转 `/membership` 展示会员状态。
- 跳过支付 → 跳转 `/` 首页(用户此时已登录,但仍为免费会员)。

### 4.3 其他检测方式的订阅门槛

**F-3.1 功能分级**

- **免费功能**:基础 23 类网站检测(当前 Home 页入口)。
- **付费功能**(需订阅对应等级会员):
  - 竞争对比检测(`--compare`)
  - AI 爬虫可访问性测试(`--crawl-test`)
  - 权威信号审计(`--authority-audit`)
  - AI 引用检测(`--citation-check`)
  - 多引擎 AI 可见性审计(`--ai-visibility`)
  - 品牌/产品/人物实体 GEO 审计(`--entity`)

**F-3.2 前端访问控制**

- 未订阅用户访问上述付费功能入口时,显示"该功能需要订阅会员"提示,并提供升级按钮触发 `PaymentModal`。
- 已订阅用户按所在等级开放对应功能。

**F-3.3 会员等级与功能映射**(建议)

| 功能              | 免费 | 基础 | 高级 | 企业 |
| --------------- | -- | -- | -- | -- |
| 基础 23 类网站检测     | ✅  | ✅  | ✅  | ✅  |
| 完整结果展示(不锁定)     | ❌  | ✅  | ✅  | ✅  |
| 修复建议(--fix)     | ❌  | ✅  | ✅  | ✅  |
| 竞争对比(--compare) | ❌  | ❌  | ✅  | ✅  |
| AI 爬虫测试         | ❌  | ❌  | ✅  | ✅  |
| 权威信号审计          | ❌  | ❌  | ✅  | ✅  |
| AI 引用检测         | ❌  | ❌  | ✅  | ✅  |
| AI 可见性审计        | ❌  | ❌  | ❌  | ✅  |
| 实体 GEO 审计       | ❌  | ❌  | ❌  | ✅  |
| 批量检测 / API      | ❌  | ❌  | ❌  | ✅  |

## 5. 业务规则

- **R-1** 锁定数量规则:每个大类免费展示数量 = `FREE_CHECKS_PER_CATEGORY = 2`,通过常量统一配置。
- **R-2** 登录态判断以 `localStorage.token` 为唯一真相源。
- **R-3** 已付费会员判定以后端 `/api/user-membership` 返回的 `is_active` 字段为准,过期会员视为免费用户。
- **R-4** 支付弹窗仅展示价格 > 0 的付费套餐,隐藏免费套餐。
- **R-5** 所有付费检测方式必须在**前端 + 后端**双重校验,前端只做 UX 引导,不可作为唯一访问控制。
- **R-6** 免费用户保留的基础 23 类检测必须完整可用,不得退化。

## 6. 页面与交互流程

### 6.1 结果页流程

```
用户检测网站 → Result 页面
  ├─ 分类摘要、总分:全部可见
  └─ 分类检测项:
      ├─ 登录+已付费:展示全部
      └─ 其他:每类前 2 个可见,其余锁定
          └─ 点击锁定卡片
              ├─ 未登录 → /login
              └─ 已登录未付费 → PaymentModal
                  ├─ 支付成功 → 刷新结果展示全部
                  └─ 跳过 → 保持锁定状态
```

### 6.2 注册付费流程

```
/register 注册 → 后端创建账号 → 自动 login 取 token
  → localStorage 存储 token → 弹出 PaymentModal
      ├─ 选择套餐 → upgradeMembership → /membership
      └─ 跳过 → /
```

### 6.3 高级功能访问流程

```
用户点击「AI 可见性审计」等付费功能
  ├─ 已订阅对应等级 → 进入功能
  └─ 未订阅 → 展示订阅提示 → 点击升级 → PaymentModal
```

## 7. 验收标准

- [ ] 未登录用户进入 Result 页,每个大类展开后仅见 2 个检测项,其余为锁定卡片。
- [ ] 登录但免费用户进入 Result 页,行为与未登录一致(仅预览 2 项)。
- [ ] 已付费会员进入 Result 页,展示全部检测项,无锁定卡片。
- [ ] 未登录用户点击锁定卡片,跳转到 `/login`。
- [ ] 已登录未付费用户点击锁定卡片,弹出 `PaymentModal`。
- [ ] 支付弹窗中完成升级后,页面自动刷新状态并展示全部结果,无需手动刷新。
- [ ] 注册新账号后,自动弹出支付弹窗;跳过后用户依然处于登录态。
- [ ] 所有付费高级检测入口对未订阅用户显示订阅提示,并能跳转升级流程。
- [ ] 中英文文案(`payment.*` / `result.*`)完整,无 i18n key 缺失。
- [ ] 后端在付费接口上验证会员等级,未订阅用户直接请求付费接口应返回 403。
- [ ] 登录态与付费态判断统一使用 `localStorage.token` + `/api/user-membership`,不使用已失效的 `user` 对象。

## 8. 非功能需求

- **性能**:锁定卡片使用纯 CSS 骨架,不发起额外请求。
- **安全**:付费校验必须由后端完成,前端显示仅为 UX 辅助。
- **国际化**:所有新增文案必须同步 `en` 与 `zh` 翻译文件。
- **可维护性**:`FREE_CHECKS_PER_CATEGORY`、会员等级到功能的映射表应集中定义,便于调整。
- **可扩展性**:会员等级(免费/基础/高级/企业)与功能矩阵应数据驱动,避免硬编码。

## 10. 风险与开放问题

1. **支付网关**:当前 `upgradeMembership` 为直接升级,未接入真实支付渠道(Stripe、微信支付、支付宝)。上线前需明确支付方案。
2. **免费试用策略**:是否对新注册用户提供 X 天的完整功能试用,以降低付费阻力?
3. **取消/退款流程**:`cancelMembership` 已存在,但缺少退款与周期内保留权益的规则定义。
4. **多设备登录**:token 目前存 `localStorage`,需明确是否支持多端同时登录及 token 失效策略。
5. **降级体验**:高级会员降级为基础后,已解锁的高级检测历史记录是否可见需决策。
