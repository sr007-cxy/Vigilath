## 一、背景与问题

当前实现存在以下断点：

1. **首页"高级检测"功能完全不可用** —— `Home.tsx` 的 6 张卡片（compare / crawlTest / authority / citation / visibility / entity）都只是 `setComingSoonKey()` 弹一个"功能即将上线"的提示，**没有任何后端对接**，但 `geo_checker.py` 实际上已经实现了对应的 6 种 CLI 子模式（`--compare` / `--crawl-test` / `--authority-audit` / `--citation-check` / `--ai-visibility` / `--entity`）。
2. **结果页过于强调"主要问题"** —— `Result.tsx` 顶部有一块 "Top critical issues" 卡片，会列出全部 FAIL/WARN，对免费会员尤其刺眼（因为他们只有 5 类，问题集中显示反而劝退）。需求方明确要求**移除该模块**。
3. **结果页的 5 个 Tab 分组与会员档位脱节** —— 当前 `categoryGroups` 是基于"网站基础 / AI 优化 / 内容质量 / 技术性能 / 外部信号" 的硬编码分组，与《会员功能免费与付费功能项目列表.md》第 265 行定义的 **5 组分组**（🛡️ 基础设施与安全 / 🤖 AI 爬虫与抓取规范 / 📑 元数据与结构化 / 📝 内容可读性与质量 / 🌐 权威与外部信号）**完全不一致**。需要按会员文档重构。
4. **免费会员的"未执行"大类没有占位展示** —— 当前免费会员只能看到 5 个 Tab 中有数据的部分，**剩余 18 个未执行类别**没有作为"已锁定"占位卡呈现，导致用户看不到完整的能力地图，转化路径不清晰。需求方要求："免费会员只执行 5 项基础检测 17 个子检测，**其他大类也展示，但是不走执行**，用户点击 tab 时显示锁定占位。"

#### 3.1.3 全部 23 大类展示，未执行的显示锁定占位（G4 / G5）

**当前行为**：`groupStats.filter((g) => g.total > 0 || g.lockedInTab > 0)` 只展示有数据或在锁定集合内的 Tab，但**锁定的类别只有在 `lockedCategorySet` 包含时才会进入 `presentCategories`**——而免费会员的 `result.locked_categories` **已经由后端正确填充**，所以 5 个 Tab 都会出现，未执行的类别会以 `renderLockedPlaceholder` 显示。

**需要确认/调整的点**：
1. **每个 Tab 的"小计"显示**：当前 `groupStats` 算的是 `passed/total`，其中 `total` 只统计已有数据的 check 数量。应改为：
   - `tabSize` = 该 Tab 下所有大类数量（包括锁定的，例如 infraSecurity = 3）。
   - `executedSize` = 该 Tab 下已执行的大类数量（免费会员在 infraSecurity 下执行了 HTTPS + Mobile-Friendliness 两个 = 2）。
   - Tab 标签徽章显示 `executedSize/tabSize`，让用户一眼看到"这个 Tab 还有 1 类没解锁"。
2. **Tab 切换不再过滤为 0** —— 取消 `g.total > 0 || g.lockedInTab > 0` 这层 filter，**始终展示全部 5 个 Tab**（即使该 Tab 在某种异常情况下完全为空，也展示空状态）。
3. **占位卡 CTA 文案** —— 沿用现有 `renderLockedPlaceholder` 的 `result.paywall.unlockCategory`（"升级检测会员解锁本项检测 →"），点击触发 `handleUnlockClick`（已实现：未登录跳 login，已登录弹 PaymentModal）。

#### 3.1.6 可视化重设计：图标 + 兜底 list（G7）

**核心原则**：**不重写检测结果数据结构**（成本太高，子进程 stdout 解析改造影响面大），而是在前端的 `parse-time` 之外，对**几个高价值大类**做"二次解析"——从 `check.message` 文本里抽取关键事实，渲染成图标卡片。其它大类继续沿用 `renderRow` 的紧凑列表（即"一列一列展示"的兜底）。

##### 3.1.6.1 总体策略

| 大类 | 是否做可视化卡 | 提议渲染 |
|---|:---:|---|
| **HTTPS** | ✅ | 大盾牌 icon + 绿/红状态 + 一句话结论 |
| **robots.txt** | ✅ | **AI 爬虫许可矩阵**：6-8 个 bot logo（GPTBot / ClaudeBot / PerplexityBot / Google-Extended / CCBot 等）+ ✓/✗ 状态色 |
| **sitemap.xml** | ✅ | 文件状态 + URL 数量大数字 + lastmod 覆盖率进度条 |
| **Meta Tags** | ✅ | 6 个子项的网格 chip：title / description / canonical / OG / lang / hreflang，每个一个 mini icon |
| **Mobile & Weight** | ✅ | 4 个仪表盘式 badge：viewport / HTML 大小 / 内联资源 / 缓存头 |
| **Cross-Platform Content Distribution** | ✅ | 平台徽标网格（X / LinkedIn / YouTube / GitHub / Reddit / Medium / Quora 等），命中=亮色 unmatch=灰 |
| **Schema Breadcrumbs & Knowledge Panel** | ✅ | Wikipedia / Wikidata / Google KP 的 3 个圆形状态徽章 |
| **AI Crawl Readiness** | ✅ | 与 robots.txt 联动的 bot 测试矩阵（HTTP 实测结果） |
| **Structured Data** | ✅ | 命中的 schema.type 标签云 |
| **Social Signals** | ✅ | 同 Cross-Platform 但单独显示 sameAs 命中 |
| 其它 13 大类 | ❌ 兜底 | 沿用现有 `renderRow` 一行式列表 |

> 二次解析失败（regex 没匹配上）时，**自动 fallback 到列表渲染**——确保任何情况下都有内容显示，绝不"白屏"。

### 3.2 首页（`frontend/src/pages/Home.tsx`）— 高级检测接通后端（G1）

#### 3.2.1 当前状态

`advancedCards` 6 张卡片定义了 key：`compare / crawlTest / authority / citation / visibility / entity`，`handleAdvancedClick` 仅做权限判断后弹"功能即将上线"。

#### 3.2.2 目标行为

每张卡片对应一个 `geo_checker.py` 的 CLI 子模式：

| 卡片 key | CLI flag | 入参 | 是否需付费 | 是否需 API key |
|---|---|---|---|---|
| `compare` | `--compare URL [URL ...]` | 要对比的多个网址 | ✅ 检测会员 | ❌ |
| `crawlTest` | `--crawl-test URL` | 单个网址 | ✅ 检测会员 | ❌ |
| `authority` | `--authority-audit URL` | 单个网址 | ✅ 检测会员 | ❌ |
| `citation` | `--citation-check URL` | 单个网址 | ✅ 检测会员 | ✅ `PERPLEXITY_API_KEY` |
| `visibility` | `--ai-visibility URL [--queries ...]` | 网址 + 可选 prompt 列表 | ✅ Starter+ | ✅ 至少一个 LLM key |
| `entity` | `--entity NAME [--entity-type TYPE]` | 实体名 + 类型 | ✅ Starter+ | ✅ `OPENAI_API_KEY` |

> 上表中"是否需付费/API key"是基于 `geo_checker.py` 注释（如 line 4977 `--ai-visibility` 注释说明 "Requires at least one of PERPLEXITY_API_KEY, OPENAI_API_KEY, ANTHROPIC_API_KEY"）和会员文档第 130 行 Starter "海外主流 LLM 收录规范" 推导。

#### 3.2.3 后端：新增 `/api/check/advanced` 端点

**位置**：`backend/app/api/geo.py`

**接口设计**：
```python
POST /api/check/advanced
Body:
{
  "mode": "compare" | "crawl_test" | "authority" | "citation" | "visibility" | "entity",
  "url": "https://example.com",          // 对 entity 模式可省略
  "compare_urls": ["https://a", ...],    // 仅 compare
  "queries": ["q1", "q2"],               // 仅 visibility
  "entity_name": "MyBrand",              // 仅 entity
  "entity_type": "brand"                 // 仅 entity, 默认 brand
}

返回：
{
  "mode": "...",
  "tier": "free" | "pro" | "starter" | ...,
  "raw_output": "<完整 stdout 文本>",
  "parsed": { ... mode-specific ... } | null,
  "locked": false                        // 若 tier 不足，返回 locked=true + 不执行
}
```

**鉴权 + 配额**：复用 `_resolve_membership_from_request`。每个 `mode` 设定最低 tier 要求（见 3.2.2 表格），不满足则返回 `403 + locked=true`。配额走现有 `check_and_increment_quota`。

**子进程调用**：复用 `run_geo_check` 的 `subprocess.Popen` 模式，但参数列表按 mode 拼接，例如：
- `compare` → `python -m geo_checker --compare URL1 URL2 ...`
- `crawl_test` → `python -m geo_checker --crawl-test URL`
- `entity` → `python -m geo_checker --entity NAME --entity-type TYPE`

**结果解析**：本期暂不深度结构化，直接把 stdout 文本（去 ANSI）原样返回，前端用 `<pre>` 渲染 + 简易高亮（PASS/WARN/FAIL 着色）。**深度结构化下一期再做**。

#### 3.2.4 前端：高级卡片改造

**入口路由**：新增 `/advanced/:mode`（例如 `/advanced/citation`），由新页面 `pages/Advanced.tsx` 承接。

**Advanced 页面元素**：

- 入参表单：
  - `compare` → 多行 URL textarea（≥2 行）
  - `crawlTest / authority / citation / visibility` → 单 URL input
  - `visibility` → URL + 多行 query textarea（可选，留空走默认 prompt）
  - `entity` → entity name + entity type 下拉（brand / product / person）

## 七、风险与备注

1. **Subprocess 执行时间**：`--ai-visibility` 实际会调多个 LLM，单次可能 60s+。`/check/advanced` 沿用 30 分钟超时即可，但前端需要 loading 态友好。**本期同步调用，不做 SSE**——若用户反馈卡顿，下一期再升级 SSE。
2. **API key 缺失的失败语义**：`geo_checker.py` 在 key 缺失时是直接 print 报错并 `sys.exit`，子进程会 returncode≠0。后端要把这种情况识别为"配置缺失"而不是"系统故障"，给前端返回明确文案。
3. **5 组分组的 i18n key 命名**：本文档采用 `infraSecurity / aiCrawl / metadataStructured / contentReadability / authorityExternal`，**与中文文档第 265 行对齐**。如团队偏好其他命名（如 `groupA-E`），P1 阶段开工前确认。
4. **`Home.tsx` 第 251 行的 `<div type="button">`** 是个 React 警告（div 没有 type 属性），改造时顺手修掉。
5. **23 类大类字符串硬编码两份**（前端 `categoryGroups` + 后端 `ALL_CHECK_CATEGORIES`）：**本期不重构**，但变更时务必两边同步。下一期可考虑后端 `/api/categories` 接口下发，前端不再硬编码。
