## 二、后端改动

### 2.1 数据模型（DB schema）

#### `memberships` 表（已存在，仅改种子数据 + 新增字段）

- 删除/停用旧 4 档
- 新增 2 档：免费会员（¥0）、检测会员（¥19.9/月）
- 新增字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `monthly_check_quota` | `INT NOT NULL` | 每月检测配额（0 = 无限） |
| `allowed_check_categories` | `TEXT` | JSON 数组，列出该档可访问的检测大项；`NULL` = 全部 23 项 |
| `tier_type` | `ENUM('saas', 'service') DEFAULT 'saas'` | 区分订阅型/咨询型 |

#### `service_tiers` 表（可选 — 推荐合并到 `memberships`）

```sql
CREATE TABLE service_tiers (
  id INTEGER PRIMARY KEY,
  slug TEXT UNIQUE,           -- 'starter' / 'growth' / 'scale'
  name TEXT,
  price_min_usd INT,
  price_max_usd INT,
  features_json TEXT,         -- 5 维度服务内容
  display_order INT
);
```

> **推荐方案**：直接在 `memberships` 表里加一条 `tier_type='service'` 的记录，省一张表。单一档位表 / 5 行记录 / 前端只查一次。

#### `user_check_usage` 表（新建，配额跟踪）

```sql
CREATE TABLE user_check_usage (
  user_id INTEGER,
  year_month TEXT,            -- '2026-04'
  used_count INT DEFAULT 0,
  PRIMARY KEY (user_id, year_month)
);
```

#### `anonymous_check_usage` 表（新建，匿名免费用户限流）

```sql
CREATE TABLE anonymous_check_usage (
  ip_hash TEXT,
  year_month TEXT,
  used_count INT DEFAULT 0,
  PRIMARY KEY (ip_hash, year_month)
);
```

> **注意**：匿名用 IP 哈希（不存原 IP），符合隐私要求。

### 2.2 `geo_checker.py` 改造

**两种方案**：

**方案 A — CLI 加 `--tier` 参数**：

```python
FREE_TIER_CHECKS = [
    "check_https",
    "check_robots_txt",
    "check_sitemap",
    "check_meta_tags",
    "check_mobile_and_weight",
]

def run_checks(url, tier="paid"):
    checks = FREE_TIER_CHECKS if tier == "free" else ALL_CHECKS
    for check_name in checks:
        ...
```

**方案 B — SaaS 层过滤（推荐）**：保留 CLI 全跑 23 项的现状，在 SaaS 服务层调用时传一个 `allowed_categories` 白名单，跑完后过滤结果。CLI 与 SaaS 解耦更干净，CLI 用户体验不变。

### 2.3 API 端点

| 端点 | 鉴权 | 行为 |
|---|---|---|
| `POST /api/check/anonymous` | 无 | 按 IP 限流（3 次/月），运行 5 项基础检测，返回精简结果 |
| `POST /api/check` | Bearer Token | 查用户档位 → 查配额 → 决定运行 5 项还是 23 项 → 写入 `user_check_usage` |
| `GET /api/memberships` | 无 | 返回前 2 档 SaaS，供 `/products-services` 渲染 |
| `GET /api/service-tiers` | 无 | 返回后 3 档人工服务（如果合并到 memberships 表，与上一条合并为一个） |
| `POST /api/contact-sales` | 无 | 接收 Starter / Growth / Scale 的咨询表单，写入 `sales_leads` 表 + 邮件通知 |
| `GET /api/users/me/usage` | Bearer Token | 返回当月已用 / 配额 / 剩余 |

### 2.4 配额中间件

每个 `/api/check` 调用前的钩子：
1. 取当前用户 → 查 `memberships.monthly_check_quota`
2. 查 `user_check_usage` 当月已用次数
3. 若已用 ≥ 配额且配额非 0（无限）→ 返回 `429 quota_exceeded`
4. 否则放行，执行后 `used_count += 1`
5. 月初定时任务清零（或按 `year_month` 自然分桶，无需显式重置）

## 三、前端改动

### 3.1 `ProductsServices.tsx` 全面重构

**当前**：只渲染 i18n 的 3 档人工服务卡片。

**改造为**：

1. 组件挂载时**并行调用**两个 API：
   - `membershipApi.getMemberships()` —— 拿 2 档 SaaS
   - `serviceTiersApi.getTiers()` —— 拿 3 档人工服务（或合并为一次调用）
2. 把两组数据按 `display_order` 排序后渲染成 5 张卡片
3. 每张卡片的 **CTA 按钮不同**：
   - **免费会员** → "立即试用"，跳到首页 URL 输入框（无需登录）
   - **检测会员** → "立即订阅 ¥19.9/月"，跳到登录/注册 + 支付流程
   - **Starter / Growth / Scale** → "联系销售"，打开咨询表单 modal
4. 已登录用户多渲染一个状态条，显示当前订阅档位（若有）

### 3.2 `Membership.tsx` 精简为"会员中心"

**当前**：套餐浏览 + 当前订阅状态混合。

**改造为**：
1. 路由守卫：未登录直接 redirect 到 `/login`
2. 只显示：当前套餐、到期时间、剩余检测次数、续费按钮、取消按钮
3. **删除**套餐卡片 grid（已迁移到 `/products-services`）
4. **删除** FAQ section（迁移到 `/products-services`）

### 3.3 首页 `Home.tsx` 调整

匿名用户在首页输入 URL 即可发起检测（**走 `/api/check/anonymous`**）。
- 检测前端不需要登录 prompt
- 结果页只展示 5 项基础结果
- 在结果页底部展示 **"解锁完整 23 项检测 · 升级到检测会员"** 升级提示

### 3.4 `Result.tsx` 处理两种结果

根据 API 返回的 `tier` 字段决定：
- `tier=free` → 只渲染 5 项检测，其余 18 项以"🔒 升级解锁"占位
- `tier=paid` → 渲染全部 23 项

### 3.5 i18n

把 `productsServices.services` 数组从 3 项扩展到 5 项（或者**重构为完全后端驱动**，i18n 只保留通用文案）。

> **推荐后端驱动** —— 产品定价改动不需要发版。

## 四、数据迁移

**风险点**：现网可能已有用户订阅旧的 ¥99 / ¥299 / ¥999 套餐。

迁移脚本步骤：
1. 在 `memberships` 表新增列前先 `BACKUP TABLE memberships`
2. 标记旧 4 档 `is_legacy = TRUE`，**不直接删除**
3. 插入新 2 档（免费 / ¥19.9）
4. 对现有 `user_memberships` 做映射：
   - 旧"免费版" → 新"免费会员"
   - 旧"基础会员 ¥99" → 新"检测会员 ¥19.9"，**保留剩余订阅期**，差价处理需产品决定（退款 / 抵扣 / 直接降级到期换档）
   - 旧"高级会员 ¥299" / "企业会员 ¥999" → 通知用户升级到人工服务，期间临时降级到检测会员
5. 通知邮件给所有受影响用户
6. 旧档位卡片在 14 天后从 `/api/memberships` 接口隐藏

## 六、实施顺序（建议 4 个 Phase）

### Phase 1 — DB & 后端基础（无前端可见变化）

1. 加 `monthly_check_quota` / `allowed_check_categories` / `tier_type` 字段
2. 写迁移脚本（旧档位标记为 legacy）
3. 插入新 2 档 + 3 档人工服务记录
4. 新建 `user_check_usage` / `anonymous_check_usage` 表
5. 实现配额中间件 + `/api/check/anonymous` 端点

### Phase 2 — 检测分级（geo_checker SaaS 层）

1. SaaS 服务层根据 `allowed_check_categories` 过滤检测结果
2. `/api/check` 接入配额逻辑
3. 后端单测：5 项 vs 23 项的结果差异

### Phase 3 — 前端重构

1. `ProductsServices.tsx` 渲染 5 档
2. `Membership.tsx` 精简为会员中心
3. `Home.tsx` 接入匿名检测
4. `Result.tsx` 区分 free/paid 结果展示
5. 路由调整：`/membership` 路由守卫；`/products-services` 加咨询表单 modal

### Phase 4 — 支付 + 数据迁移上线

1. 支付 provider 创建新 SKU
2. 灰度发布给少量用户验证
3. 执行数据迁移脚本
4. 发送用户通知邮件
5. 全量发布

## 七、风险与开放问题

| 风险 | 说明 | 缓解 |
|---|---|---|
| **存量用户体验** | 现有 ¥99 / ¥299 / ¥999 订阅用户被强制降级 | 提前 14 天邮件通知 + 退差价 / 服务期延长 |
| **匿名滥用** | IP 限流可被绕过（VPN / 移动网络） | 上 Cloudflare Turnstile 或 reCAPTCHA |
| **检测分级合理性** | 5 项免费可能太少 / 太多 | 上线后看转化漏斗，6 周内复盘是否调整 |
| **Service tier 与 SaaS tier 数据合并** | 用同一张 `memberships` 表 vs 拆两张表 | 推荐合并，加 `tier_type` 字段区分 |
| **`/membership` 是否完全废弃** | 老书签会 404 | 保留路由作为会员中心，未登录自动 redirect |
| **`geo_checker.py` CLI 改造** | CLI 用户期望全跑 23 项 | SaaS 层过滤，CLI 行为不变 |

## 八、需要拍板的决策点

1. **存量 ¥99 / ¥299 / ¥999 用户**怎么处理？退差价 / 抵扣到检测会员 / 服务期延长 / 直接降级？
