## 1. 顶层 `generate_score` 并发化(P0 头号)

### 1.1 背景

post-refactor baidu 基线 **124 秒**,其中 25 个 `check_*` 串行跑。每个 check 对 baidu 的慢服务器都要等几秒,累加 = 总时。但这些 check **互相独立**(只有 `check_multi_page` 依赖 `check_sitemap` 的返回),并发跑完全可行。

预期收益:
- baidu **124 s → ~42 s**(bound by `check_technical_crawlability` 的 42 s)
- example **5 s → ~1.5 s**

这是**投入/产出比最高的一项**,也是后续所有单 check 内部优化收益的放大器。

### 1.2 改动文件

| 文件 | 说明 |
|---|---|
| `backend/geo_checker/orchestrate.py::_run_checks` | 主改,循环改 ThreadPoolExecutor |
| `backend/geo_checker/state.py` | `_scores` 加 `threading.Lock`;`_page_cache` 的 get-or-set 也加锁 |
| `backend/geo/services/geo_checker.py` | `redirect_stdout` 换成 `_ThreadLocalStdout`(范式在 `advanced_runners.py`) |

package 重构后只有一份核心代码,不再需要"两份同步改"。

### 1.3 代码骨架

#### `state.py` 加锁

```python
import threading

_scores_lock = threading.Lock()
_page_cache_lock = threading.Lock()


def track_score(category, earned, max_points):
    with _scores_lock:
        if category not in _scores:
            _scores[category] = {"earned": 0.0, "max": 0.0}
        _scores[category]["earned"] += earned
        _scores[category]["max"] += max_points
```

#### `io.py` fetch 加锁(避免并发 miss 重复抓)

```python
from . import state as _state

def fetch(url, timeout=15, allow_redirects=True):
    with _state._page_cache_lock:
        if url in _state._page_cache:
            return _state._page_cache[url]
    # 释放锁后再发请求,避免锁内做慢 I/O
    try:
        resp = requests.get(url, timeout=timeout, allow_redirects=allow_redirects,
                            headers={"User-Agent": "GEO-Readiness-Checker/1.0"})
        with _state._page_cache_lock:
            _state._page_cache[url] = resp
        return resp
    except requests.RequestException:
        return None
```

#### `orchestrate.py::_run_checks` 改并发

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

def _run_checks(base_url, allowed_categories=None):
    allowed_set = set(allowed_categories) if allowed_categories else None

    def _should_run(label):
        return allowed_set is None or label in allowed_set

    # check_sitemap 必须先跑:其返回的 sitemap_urls 传给 check_multi_page
    sitemap_urls = []
    if _should_run("sitemap.xml"):
        sitemap_urls = check_sitemap(base_url)

    # 其余 24 个并发
    runnable = [
        (label, fn) for label, fn in CHECK_REGISTRY
        if fn != "__sitemap__" and _should_run(label)
    ]
    with ThreadPoolExecutor(max_workers=10) as pool:
        futures = [pool.submit(fn, base_url, sitemap_urls) for _label, fn in runnable]
        for fut in as_completed(futures):
            fut.result()  # 让异常冒出
    return sitemap_urls
```

#### backend 层:换掉 `redirect_stdout`

`backend/geo/services/geo_checker.py` 里 `with redirect_stdout(buf)` 改成:

```python
# 用 advanced_runners 的 _ThreadLocalStdout 范式 —— 每请求独立 buf,
# 不再全局改 sys.stdout,避免线程间串扰
from geo.services.advanced_runners import _stdout_proxy
_stdout_proxy._state.buf = buf
try:
    _gc_orchestrate.generate_score(url, allowed_categories=allowed_categories)
finally:
    _stdout_proxy._state.buf = None
```

`_geo_checker_lock` **暂时保留**(双重保护;#14 完成后可在后续 PR 移除)。

### 1.4 验收标准

- baidu.com:`block=default_check` 从 124 s → **< 50 s**
- example.com:`block=default_check` 从 5 s → **< 2 s**
- 对同一 URL 连续跑 3 次,各类别得分偏差 **= 0**(锁必须工作)
- 2 个请求并发跑(`curl` 同时发 2 个 baidu),各自拿到正确结果,不串扰
- nginx log 无 5xx 增加

### 1.5 风险与回滚

| 风险 | 缓解 |
|---|---|
| `_scores` 并发累加数据错乱 | `threading.Lock` 包 `+=`;回归测试对比 score 一致 |
| 多线程同时 fetch 同 URL 翻倍请求量 | `fetch` 的 lock-check-unlock-fetch-lock-store 模式;worst case 2x fetch 但无功能问题 |
| `print` 交错到 stdout,`parse_geo_output` 解析错乱 | 关键看每行的 `--- Section ---` 标识完整(换行符在同一个 `print()` 调用里,GIL 下单行原子),多线程交错也是**行级别**交错,解析器按行独立处理。若仍需要确定性,改成 queue + 主线程统一 flush |
| `_geo_checker_lock` 保留导致只是移锁 | 本方案**保留**锁,但 `_run_checks` 内部已并发,锁只是防跨请求干扰。单请求内的 25 个 check 已经并发 |

回滚:`git revert`,restart 后验证 baidu 回到 124 s 量级。

## 3. `check_technical_crawlability` 内部并发(P0 第 2 步)

### 3.1 背景

post-refactor baidu 基线 42 s,占总时 34%。顶层并发(§1)完成后,它决定单请求总时底线。拆完 baidu 总时能从 42 s 再降到 17-25 s。

根因:`checks.py::check_technical_crawlability` 内部最坏 22 次串行 HTTP(见 `issue_list.md` #13)。

### 3.2 改动文件

只改 `backend/geo_checker/checks.py::check_technical_crawlability`。

### 3.3 代码骨架

拆成 4 组独立的并发子任务,每组返回一个 dict 结果供主线程汇总打印:

```python
from concurrent.futures import ThreadPoolExecutor

def check_technical_crawlability(base_url):
    print("\n--- Technical Crawlability ---")
    resp, soup = get_soup(base_url)
    if not soup:
        emit_check(FAIL, "result.checks.tech_crawl.fetch_failed", "Could not fetch homepage")
        track_score("Technical Crawlability", 0, 5)
        return

    # 从 soup 取出 canonical / feeds(纯内存,无 HTTP)
    canonical = soup.find("link", rel="canonical")
    canonical_url = urljoin(base_url, canonical["href"]) if canonical and canonical.get("href") else None
    feeds = soup.find_all("link", type=re.compile(r"(rss|atom)\+xml", re.IGNORECASE))

    # 4 组独立子任务
    def _task_canonical():
        if canonical_url and canonical_url.rstrip("/") != base_url.rstrip("/"):
            return fetch(canonical_url)  # 1 次 HTTP
        return None

    def _task_redirect():
        try:
            return requests.get(base_url, allow_redirects=False, timeout=10,
                                headers={"User-Agent": "GEO-Readiness-Checker/1.0"})
        except requests.RequestException:
            return None

    def _task_http2():
        try:
            return subprocess.run(
                ["curl", "-sI", "--http2", "-o", "/dev/null", "-w", "%{http_version}", base_url],
                capture_output=True, text=True, timeout=10
            ).stdout.strip()
        except Exception:
            return ""

    def _task_feed_and_api():
        # feed probe 6 路径 + api probe 10 路径
        feed_paths = ["/feed", "/feed.xml", "/rss.xml", "/atom.xml", "/rss", "/blog/feed"]
        api_paths = ["/api", "/api/v1", "/graphql", "/openapi.json", "/openapi.yaml",
                     "/swagger.json", "/docs/api", "/webhooks", "/integrations", "/developers"]

        with ThreadPoolExecutor(max_workers=16) as pool:
            feed_futs = {p: pool.submit(fetch, urljoin(base_url, p), 5) for p in feed_paths}
            api_futs = {p: pool.submit(fetch, urljoin(base_url, p), 5) for p in api_paths}
            feed_results = {p: f.result() for p, f in feed_futs.items()}
            api_results = {p: f.result() for p, f in api_futs.items()}

        # 主线程按原顺序 pick first match
        feed_url = None
        for p in feed_paths:
            r = feed_results.get(p)
            if r and r.status_code == 200 and ("<rss" in r.text or "<feed" in r.text):
                feed_url = urljoin(base_url, p)
                break
        api_hits = [
            (p, label) for p, label in [
                ("/api", "API base path"), ("/api/v1", "Versioned API"),
                ("/graphql", "GraphQL"), ("/openapi.json", "OpenAPI"),
                # ... 其他 label
            ]
            if (r := api_results.get(p)) and r.status_code == 200 and len(r.text.strip()) > 100
        ][:3]
        return feed_url, api_hits

    with ThreadPoolExecutor(max_workers=4) as pool:
        canon_fut = pool.submit(_task_canonical)
        redir_fut = pool.submit(_task_redirect)
        http2_fut = pool.submit(_task_http2)
        feed_api_fut = pool.submit(_task_feed_and_api)

        canon_resp = canon_fut.result()
        redir_resp = redir_fut.result()
        http_version = http2_fut.result()
        feed_url, api_hits = feed_api_fut.result()

    # 以下 emit_check / track_score 逻辑不变,按各 future 结果照写
    # ...
```

### 3.4 验收

- baidu `func=check_technical_crawlability elapsed_ms` 从 42 000 → **< 12 000 ms**
- example 1 000 → < 400 ms
- 配合 §1,baidu 总时 < 25 s

### 3.5 风险与回滚

| 风险 | 缓解 |
|---|---|
| 16 并发打自家站点导致 429 / WAF | 用的是 `fetch` 带统一 UA,单站点 16 连接无压力;出问题降到 8 |

## 8. `_page_cache` 迁 Redis

**当前**:`geo_checker.py:201` 的 `_page_cache` 是进程内 dict,4 workers 各一份,重启丢失。

**方向**:用 Redis 做共享缓存,key = `url`,value = gzip 后的 response body + status code + headers 子集,TTL 1 小时。

**需要**:运维配合部署 Redis(EC2 本机 or managed),估算一个 URL 缓存 ~100 KB,1000 个 URL 约 100 MB。

**设计评审要点**:多 worker 并发 miss 时的 thundering herd、缓存击穿时 SingleFlight 锁、大站点 body 可能超 1 MB 的截断策略。

---

## 9. 去 `_geo_checker_lock`

**当前**:`backend/geo/services/geo_checker.py:26` 的全局锁,把单 worker 内的请求完全串行化。根因是核心 `geo_checker.py` 用了一堆模块级全局状态(`_scores` / `_page_cache` / `SHOW_FIX` / `redirect_stdout`)。

**方向**:把这些全局态改成 `contextvars.ContextVar` 或函数显式参数,`redirect_stdout` 改成线程局部代理(`advanced_runners.py` 里的 `_ThreadLocalStdout` 已经有先例)。

**风险**:重构面大,可能破坏 CLI 用法。需要先整理出所有"被模块级共享"的变量清单,再决定是每个都挪还是保留一个 Context 对象贯穿。

**前提**:必须先通过 P1.7 的错误分层,确保异常路径可观测,再动这块。

### A.1 串行改并发的模板

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

def _do_one(item) -> Tuple[Any, Any]:
    try:
        # 原循环体
        return item, result
    except Exception as e:
        return item, None  # 或具体的错误标记

with ThreadPoolExecutor(max_workers=min(N, len(items) or 1)) as pool:
    futures = {pool.submit(_do_one, it): it for it in items}
    for fut in as_completed(futures):
        item, result = fut.result()
        # 主线程单独汇总,不要在 _do_one 里 print
```
