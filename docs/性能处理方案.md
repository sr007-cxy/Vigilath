## 0. 整体策略

### 0.1 目标

| 指标 | 当前 | 目标 | 达成途径 |
|---|---|---|---|
| 默认 check P95 耗时 | ~120 s | < 30 s | P0.1 + P1.4 + P1.5 |
| `/visibility` P95 耗时 | ~180 s | < 60 s | P0.2 |
| UX 型 499 率 | 13/16 | 0 | P0.3 |
| 上游 AI 故障时的错误码准确率 | 0%(全 503) | 100%(按源分层) | P1.7 |

### 0.2 执行顺序的理由

1. **先做 P0.1**(`check_cross_platform` 并发化)—— 纯后端、<20 行、无接口变更、立即见效。
2. **再做 P0.2**(`/visibility` 参数收敛)—— 纯常量调整、无结构改动、可随时回退。
3. **最后做 P0.3**(前端检测触发改造)—— 前端改动面大,需要单独 QA 验证。

P0 三步做完后默认 check 应该稳定在 30 s 内,UX 型 499 清零,基本不再有告警。再按 P1 顺序迭代。

## P0 — 当前批次

## 1. `check_cross_platform` 并发化

### 1.1 背景

串行探测 10 个社交平台,每个 `timeout=8 s`,最坏 80 s。根因与数据见 `performance-guide.md` 第 4.1 节。

### 1.2 改动文件

| 文件 | 行号 | 说明 |
|---|---|---|
| `geo_checker.py`(项目根) | 2784 起 | 高级路径 + CLI 使用 |
| `geo_checker/__main__.py` | 1851 起 | 默认 API 路径使用 |

两个文件都要改,**改动一致**。

### 1.3 代码骨架

把原来的:

```python
for plat_name, plat_info in platforms_to_probe.items():
    found = False
    for probe_url in plat_info["probe_urls"]:
        try:
            r = requests.get(probe_url, timeout=8, allow_redirects=True, headers={
                "User-Agent": browser_ua
            })
            # ... 平台判定逻辑 ...
        except requests.RequestException:
            pass
    probed[plat_name] = (found, url_found)
```

改成:

```python
from concurrent.futures import ThreadPoolExecutor

def _probe_single(plat_name, plat_info):
    """Probe one platform; returns (plat_name, found, url_or_none)."""
    for probe_url in plat_info["probe_urls"]:
        try:
            r = requests.get(probe_url, timeout=8, allow_redirects=True, headers={
                "User-Agent": browser_ua
            })
            # ... 把原来循环体里的判定逻辑整体搬过来 ...
            if found:
                return plat_name, True, probe_url
        except requests.RequestException:
            continue
    return plat_name, False, None

# 最多 10 平台,用 10 并发;ThreadPool 轻量,不用担心线程开销
with ThreadPoolExecutor(max_workers=min(10, len(platforms_to_probe) or 1)) as pool:
    results = pool.map(
        lambda args: _probe_single(*args),
        platforms_to_probe.items(),
    )
for plat_name, found, url_found in results:
    probed[plat_name] = (found, url_found)
```

**注意**:`_probe_single` 里不要 `print`,避免多线程输出交错——把原本的打印逻辑延后到主线程根据 `probed` 字典再打。

### 1.4 验收标准

- `check_cross_platform elapsed_ms` 从 2500–80000 ms 降到稳定 < 10000 ms
- 检测结果中各平台"是否找到"的数据与改前一致(用一个已知站点对比)
- 对 baidu.com 跑一次,整体 `block=default_check` 从 ~120 s 降到 < 40 s

### 1.5 风险与回滚

| 风险 | 缓解 |
|---|---|
| 多线程同时打同一平台被 rate-limit | 平台各自独立,不会 |
| 平台返回异常 HTML 导致判定逻辑出错 | 判定逻辑不变,只是并发执行 |
| 影响 CLI 输出顺序 | 把 `print` 挪到主线程收集 `probed` 之后 |

回滚:一次 `git revert`,`systemctl restart geo-checker.service`。

## 3. 前端检测触发改到 Result 页 + AbortController

### 3.1 背景

当前 Home 发起 API 请求后用户按返回键/刷新 → 组件卸载 → 请求中断 → nginx 499。根因与数据见 `performance-guide.md` 第 4.2 节和 `performance-report-2026-04-16.md` 第 3.1 节。

### 3.2 改动文件

| 文件 | 内容 |
|---|---|
| `frontend/src/pages/Home.tsx` | 提交后**不再调 API**,直接 `navigate('/result', { state: { url } })` |
| `frontend/src/pages/Result.tsx` | `useEffect` 检测 `location.state.url` 且无 `result` 时发起 API,期间显示 `CheckProgress` |
| `frontend/src/services/geoApi.ts` | 给 `runGeoCheck` / `checkGeo` 加 `signal?: AbortSignal` 参数 |
| `frontend/src/components/result/CheckProgress.tsx` | 不变 |

### 3.3 代码骨架

#### `geoApi.ts`:

```ts
async runGeoCheck(
  url: string,
  includeFix: boolean = true,
  signal?: AbortSignal,
): Promise<GeoTestResult> {
  const { path, headers } = resolveCheckRequest();
  try {
    const response = await apiClient.post(
      path,
      { url, include_fix: includeFix },
      { headers, signal },
    );
    return response.data;
  } catch (error) {
    throwApiError(error, 'Failed to run GEO check');
  }
}
```

#### `Home.tsx`(submit handler):

```tsx
const handleSubmit = (e: React.FormEvent) => {
  e.preventDefault();
  const formattedUrl = normalizeUrl(url.trim());
  if (!formattedUrl) return;
  // 不再调 API。直接跳转,检测在 Result 页发起。
  navigate('/result', { state: { url: formattedUrl } });
};
```

#### `Result.tsx`(mount-time kickoff + cleanup):

```tsx
useEffect(() => {
  const state = location.state as { url?: string; result?: GeoTestResult } | null;
  if (state?.result) {
    // 已有结果(譬如从 Home 端 navigate 带过来的),直接渲染
    setResult(state.result);
    return;
  }
  if (!state?.url) {
    navigate('/', { replace: true });
    return;
  }

  const controller = new AbortController();
  setLoading(true);
  geoApi
    .runGeoCheck(state.url, true, controller.signal)
    .then((fresh) => {
      setResult(fresh);
      navigate('.', { state: { result: fresh }, replace: true });
    })
    .catch((err) => {
      if (controller.signal.aborted) return;  // 用户主动取消,不显示错误
      setError(err.message);
    })
    .finally(() => setLoading(false));

  // 卸载时中止请求。axios 会在 signal.aborted 触发时抛 CanceledError。
  return () => controller.abort();
}, []); // only on mount
```

### 3.4 验收标准

- 在 Result 页等待期间按返回键:nginx 仍然会记 499,但**后端不再继续空跑**(通过 journalctl 看 `block=default_check` 比前端断开时间晚结束几秒内,而不是几分钟)。
- 在 Home 输入 URL 点检测 → 立刻跳转 Result(<100 ms)并显示 CheckProgress,用户感知"已在结果页",不会再想按返回。
- 前端 Network 面板:Result 页单次加载有 1 条 POST,刷新后再跳回 Home 不会重复产生检测。

### 3.5 风险与回滚

| 风险 | 缓解 |
|---|---|
| Result 页被直接深链访问(无 state.url) | 上面代码已处理:`navigate('/', replace)` 回首页 |
| 检测中途用户前进/后退,state 丢失重跑 | `location.state.result` 已 replace,前进到 Result 会直接渲染 |
| AbortController 未被 axios 正确处理 | axios 0.22+ 原生支持 `signal` |

回滚:`git revert` 前端三个文件,重新 build + rsync。

## 7. `_run_or_raise` 错误码分层

### 7.1 改动点

`backend/geo/api/advanced.py:64-75`,当前 `RuntimeError` 一律 503。

### 7.2 代码骨架

在 `backend/geo/utils/error_handler.py`(或新建 `geo/errors.py`)定义:

```python
class UpstreamAIError(RuntimeError):
    """Upstream AI API (OpenRouter / Perplexity) returned consistent errors."""

class TargetUnreachableError(RuntimeError):
    """Failed to fetch the target URL — likely client-side bad input."""

class MissingApiKeyError(RuntimeError):
    """Required API key is not configured on the server."""
```

把 `geo_checker.py` 里各自的 `raise RuntimeError("OPENROUTER_API_KEY not set")` 改成 `raise MissingApiKeyError(...)`,citation 那段"所有 query 失败"改成 `UpstreamAIError`,aeo 的 bare return 改成 `raise TargetUnreachableError(...)`。

`_run_or_raise`:

```python
except MissingApiKeyError as e:
    raise AppException(status_code=503, message=str(e))
except UpstreamAIError as e:
    raise AppException(status_code=502, message=str(e))
except TargetUnreachableError as e:
    raise AppException(status_code=400, message=str(e))
except RuntimeError as e:
    # 兜底:未知类型仍是 503
    raise AppException(status_code=503, message=str(e))
```

前端 `geoApi.ts` 的 `ApiError` 已经带 `status`,`CheckoutPending` 和 `Advanced` 页可以 switch 处理,精确提示。

### 7.3 验收

- 目标 URL 故意填错(比如 `https://this-does-not-exist.example`),端点返回 400 而非 503
- 临时撤掉 `OPENROUTER_API_KEY`,端点返回 503
- 前端错误提示能区分"目标站无法访问"和"服务暂不可用"

## P2 — 重构型待评估

## 8. `_page_cache` 迁 Redis

**当前**:`geo_checker.py:201` 的 `_page_cache` 是进程内 dict,4 workers 各一份,重启丢失。

**方向**:用 Redis 做共享缓存,key = `url`,value = gzip 后的 response body + status code + headers 子集,TTL 1 小时。

**需要**:运维配合部署 Redis(EC2 本机 or managed),估算一个 URL 缓存 ~100 KB,1000 个 URL 约 100 MB。

**设计评审要点**:多 worker 并发 miss 时的 thundering herd、缓存击穿时 SingleFlight 锁、大站点 body 可能超 1 MB 的截断策略。

---

## 9. 去 `_geo_checker_lock`

**当前**:`backend/geo/services/geo_checker.py:26` 的全局锁,把单 worker 内的请求完全串行化。根因是核心 `geo_checker.py` 用了一堆模块级全局状态(`_scores` / `_page_cache` / `SHOW_FIX` / `redirect_stdout`)。

**方向**:把这些全局态改成 `contextvars.ContextVar` 或函数显式参数,`redirect_stdout` 改成线程局部代理(`advanced_runners.py` 里的 `_ThreadLocalStdout` 已经有先例)。

**风险**:重构面大,可能破坏 CLI 用法。需要先整理出所有"被模块级共享"的变量清单,再决定是每个都挪还是保留一个 Context 对象贯穿。

**前提**:必须先通过 P1.7 的错误分层,确保异常路径可观测,再动这块。

## 附录 A: 共用代码模式

### A.1 串行改并发的模板

```python
from concurrent.futures import ThreadPoolExecutor, as_completed

def _do_one(item) -> Tuple[Any, Any]:
    try:
        # 原循环体
        return item, result
    except Exception as e:
        return item, None  # 或具体的错误标记

with ThreadPoolExecutor(max_workers=min(N, len(items) or 1)) as pool:
    futures = {pool.submit(_do_one, it): it for it in items}
    for fut in as_completed(futures):
        item, result = fut.result()
        # 主线程单独汇总,不要在 _do_one 里 print
```

### A.2 带 signal 的 axios 调用

```ts
const controller = new AbortController();
const promise = apiClient.post(path, body, { signal: controller.signal });
// 组件卸载时
return () => controller.abort();
```
