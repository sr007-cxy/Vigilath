# 引用源追溯 / 引用源偏好 / 竞品透视 — 实现方案 & 开发计划

## 一、背景

现有 `--citation-check` / `--ai-visibility` 走 OpenRouter API，但 API 返回的引用源与网页版有差异：引用数量少、缺少结构化源卡片、部分引擎 API 无联网搜索。用户需要**与网页版一致的引用源数据**来做深度分析。

**方案选择**：混合方案 — API 优先（有联网搜索的引擎），Playwright 兜底（API 无联网的引擎）。统一 `EngineAdapter` 接口，上层分析器不关心底层实现。

---

## 二、三大功能定义

### 功能 1：引用源追溯

**核心问题**：AI 引擎回答与品牌相关的问题时，引用了哪些信息源？

**输出**：
- 所有被引用源聚合列表（URL、域名、类型、引用次数、来自哪些引擎、哪些查询）
- 引用上下文片段（回答中提及该源的句子）
- 自身域名引用详情 + 哪些查询完全没引用自身
- Top 10 高频引用源

### 功能 2：引用源偏好

**核心问题**：不同 AI 引擎偏好引用什么类型的源？如何优化内容以匹配偏好？

**输出**：
- 每个引擎的源类型分布（wikipedia / news / blog / forum / review / official / docs 等占比）
- 每个引擎最常引用的域名 Top 5
- 跨引擎偏好差异对比
- 优化建议（如"Perplexity 30% 引用来自新闻源，建议增加媒体曝光"）

### 功能 3：竞品透视

**核心问题**：竞品在 AI 回答中是什么形象？比你强在哪？弱在哪？

**输出**：
- 每个竞品：被引频次、被提及次数、framing（recommended / leader / option / niche）
- 竞品优劣势描述（从 AI 回答中提取）
- 与自身品牌的对比定位
- 竞争格局总览 + 行动建议

## 三、引擎接入方案

覆盖 12 个引擎：国内 8（DeepSeek / 豆包 / 千问 / 文心 / 元宝 / GLM / Kimi / Minimax）+ 海外 4（OpenAI / Anthropic / Gemini / Mistral）。

### API 层（稳定、快、便宜） — 6 引擎

| 引擎 | API | 联网搜索方式 | 引用源返回 | 与网页一致性 | 备注 |
|------|-----|-------------|-----------|------------|------|
| **Kimi** | Moonshot API | `web_search` tool | `search_results` 结构化字段 | 高 | 国内最佳，引用源完整 |
| **通义千问** | DashScope | `enable_search=true` | `search_results` 带 URL+标题+摘要 | 高 | 阿里系，稳定 |
| **智谱 GLM** | 智谱开放平台 | `web_search` tool | 搜索结果引用 | 高 | GLM-4 系列 |
| **OpenAI** | Responses API | `web_search` tool（2025 新增） | `annotations` 带 URL+标题 | 中高 | 不走 OpenRouter，用官方 Responses API |
| **Gemini** | Gemini API | `google_search_retrieval` grounding | `grounding_metadata.grounding_chunks` 带 URL | 高 | Google 搜索做 grounding，引用源天然丰富 |
| **Perplexity** | Sonar API | 内置 | `citations` 字段 | 中高 | 搜索引擎原生，引用最完整之一 |

### Playwright 层（API 无联网搜索的兜底） — 6 引擎

| 引擎 | 原因 | 难度 | 备注 |
|------|------|------|------|
| **DeepSeek** | API 无联网搜索，网页版 DeepSeek Chat 有 | 中 | 网页版搜索质量好 |
| **豆包** | 火山引擎 API 联网搜索能力有限，网页版更完整 | 中 | 字节系，网页版引用源丰富 |
| **元宝** | 腾讯混元 API 无联网搜索，yuanbao.tencent.com 网页版有 | 中 | 腾讯系 |
| **文心一言** | API 有 `enable_search` 但引用源质量差、结构不稳定 | 中 | 百度系，优先级最低 |
| **Anthropic** | Claude API 无联网搜索，claude.ai 网页版有 | 中高 | 需要 Pro 账号 |
| **Mistral** | API 无联网搜索，Le Chat 网页版有 | 中 | 海外小众，优先级低 |

> **Minimax 待定**：需验证 hailuo API 是否支持 `web_search` tool call。若支持则归 API 层，否则走 Playwright（海螺 AI 网页版有搜索）。

### 统一接口

```python
class EngineAdapter(ABC):
    """统一接口 — 上层不关心是 API 还是 Playwright"""

    @abstractmethod
    async def search(self, query: str) -> EngineResult:
        """返回回答 + 结构化引用列表"""
        ...

    @abstractmethod
    async def is_available(self) -> bool:
        """检查引擎是否可用（API key 有效 / session 存活）"""
        ...

@dataclass
class EngineResult:
    engine: str              # "kimi" / "qwen" / "perplexity" / "deepseek" / ...
    query: str
    answer: str              # 回答全文
    citations: list[Citation]
    search_queries: list[str]  # 引擎实际执行的搜索词（如有）
    error: str | None

@dataclass
class Citation:
    url: str
    domain: str
    title: str
    snippet: str             # 引用摘要/上下文
    position: int            # 在回答中的引用位置序号
```

切换实现只需换 adapter 类，分析层零改动。未来某引擎 API 开放联网搜索，从 Playwright adapter 切到 API adapter 即可。

## 六、反检测策略（Playwright 层）

6 个 Playwright 引擎均需要（DeepSeek / 豆包 / 元宝 / 文心一言 / Anthropic / Mistral）：

```python
# anti_detect.py 核心措施
1. navigator.webdriver = false          # 屏蔽自动化标记
2. Canvas / WebGL 指纹随机化            # 防指纹追踪
3. User-Agent 真实 Chrome 版本轮换      # 匹配真实浏览器
4. viewport / timezone / language        # 匹配地区设置
5. 鼠标轨迹 + 打字延迟                  # 模拟人类行为（随机 50-200ms）
6. Cookie session 持久化                # 避免频繁登录触发风控
7. 查询间隔 3-8 秒随机                  # 避免请求过快
```

## 七、查询策略

每次分析约发送 10-15 个查询 × N 个引擎：

```
查询组 1 — 品牌定义（3 条）:
  "What is {brand}?"
  "What does {domain} do?"
  "{brand} 是什么？"

查询组 2 — 竞品对比（3 条）:
  "Best alternatives to {brand}"
  "{brand} 和竞品对比"
  "{brand} vs {competitor}"（如提供竞品名）

查询组 3 — 行业/品类（2 条）:
  "Best {category} tools 2025"
  "{category} 领域有哪些好用的工具？"

查询组 4 — 评价（2 条）:
  "{brand} review / pros and cons"
  "{brand} 评价怎么样？"

查询组 5 — 可信度（2 条）:
  "Is {brand} reliable?"
  "{brand} 靠谱吗？"
```

中英文各覆盖，确保国内外引擎都能命中。

## 八、源类型分类规则

```python
SOURCE_TYPE_RULES = {
    # 精确匹配
    "wikipedia.org": "wikipedia",
    "wikidata.org": "wikipedia",
    "zhihu.com": "forum",
    "reddit.com": "forum",
    "stackoverflow.com": "forum",
    "github.com": "code",
    "npmjs.com": "code",
    "g2.com": "review",
    "trustpilot.com": "review",
    "capterra.com": "review",
    "twitter.com": "social",
    "linkedin.com": "social",
    "weibo.com": "social",
    "36kr.com": "news",
    "techcrunch.com": "news",
    "reuters.com": "news",
    # ... 更多精确规则
}

# 启发式 fallback
def classify(url, target_domain):
    domain = extract_domain(url)
    if domain == target_domain:
        return "official"
    if domain in SOURCE_TYPE_RULES:
        return SOURCE_TYPE_RULES[domain]
    # 路径启发
    if "/blog" in url or "/posts" in url:
        return "blog"
    if "/docs" in url or "/documentation" in url:
        return "documentation"
    if "/news" in url or "/press" in url:
        return "news"
    return "other"
```

## 十三、风险 & 应对

| 风险 | 影响 | 应对 |
|------|------|------|
| Playwright 引擎网页改版 | parser 失效 | 选择器多重 fallback + 错误告警；6 个 Playwright 引擎需持续维护 |
| 反自动化检测 | 登录/查询被拦 | session 持久化 + 人类行为模拟 + 降频 |
| API 引擎联网搜索结果偏少 | 引用源数据不完整 | 可随时把该引擎切到 Playwright adapter |
| 海外引擎访问受限 | claude.ai / chat.mistral.ai 国内访问不稳定 | 部署时配置代理；或标记为可选引擎 |
| Minimax API 能力不确定 | web_search 支持存疑 | 先验证，不支持则退到 Playwright |
| 12 引擎并发耗时长 | Playwright 串行 12-15 分钟 | Playwright 多 browser context 并发；API 全并发 |
| 国内/海外 API 变更 | 接口不兼容 | 各 adapter 独立，改一个不影响其他 |
| 文心一言引用源质量差 | 分析结果价值低 | 标记为低优先级引擎，可选启用 |
