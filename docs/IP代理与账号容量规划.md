# IP 代理与账号容量规划(浏览器引擎扩容)

> 面向 **deepseek / qwen / 文心** 三个浏览器引擎的出口 IP + 账号扩容规划。
> 元宝 / 豆包是官方 API,**不占账号 / IP**,不在本文范围(产能只看 API 套餐)。
>
> ⚠️ 各平台"封号阈值"不公开,下表是**保守安全起点**;系统已记录每个账号的
> `captcha_count` / `login_lost` 信号,**上线后按真实信号校准**(那才是最硬的数据)。

---

## 一、当前现状与瓶颈

| 项 | 现状 | 是否瓶颈 |
|---|---|---|
| 引擎(模型) | 5 个:deepseek/qwen/文心(浏览器)+ 元宝/豆包(API) | — |
| deepseek 账号 | 17 active(含部分掉登录) | 账号够,有效 IP 不够 |
| qwen 账号 | **4** | ⚠️ 偏少 |
| 文心 账号 | **2** | ⚠️ 太少 |
| 出口 IP | **4**(都是 worker 主机自身 IP) | 🔴 **核心瓶颈** |
| deepseek 日上限 | **30 / 天(全局)** | 🔴 因 IP 少被压太低 |
| 元宝 / 豆包 | API,无账号 / IP 约束 | ✅ 不卡 |

**结论:瓶颈 = 出口 IP 太少 → 日上限不敢提 → 账号利用不起来。加 IP 池直接解。**

## 二、各引擎安全限度(保守起点)

| 引擎 | 通道 | 安全 /账号/**天** | 安全 /账号/**小时** | 风控严格度 |
|---|---|---|---|---|
| deepseek | 浏览器 | ~25–30 | ≤ ~6(带人类间隔) | 高 |
| qwen 通义 | 浏览器 | ~40–50 | ≤ ~10 | 中 |
| 文心 | 浏览器 | ~40–50 | ≤ ~10 | 中 |
| 元宝 | API(SearchPro+deepseek 合成) | 按腾讯套餐 | 套餐 QPS | 无封号 |
| 豆包 | API(火山 ARK) | 按 ARK 配额 | ARK 限频 | 无封号 |

**单个 IP 的请求量** = 它挂的各账号"安全/天"之和。
例:1 个 IP 挂 deepseek + qwen + 文心 各 1 号 → 该 IP 每天承载 ≈ 30 + 50 + 50 = **130 次/天**,
但**单平台看到的不超过该账号的限度**(deepseek 平台只看到 30)。

## 三、封号 / 风控触发规则(按危险度)

| # | 触发因素 | 对策 |
|---|---|---|
| 1 🔴 | **账号换 IP(异地登录)** —— 最大杀手 | **静态 IP + 账号↔IP 粘定**(session-id=账号id) |
| 2 🔴 | 请求太快 / 太密(无人类间隔、整点爆发) | 控速 + 随机延时,按日上限分散 |
| 3 🟠 | 同平台多号挤一个 IP | 一个 IP 该平台**只放 1 个号**(不同平台可叠) |
| 4 🟠 | 机房 IP(vs 住宅) | 选住宅 / ISP 静态 |
| 5 🟠 | 单号日量持续过高 | 控在安全线内,按 captcha 信号校准 |
| 6 🟢 | 浏览器指纹露馅 | 已用 cloakbrowser / patchright 反检测 |

**关键纪律:同一账号必须始终走同一个 IP。**

## 四、账号 / IP 规划(1 IP = 3 平台各 1 号)

| 规模 | IP(通道) | 账号(每引擎) | 总账号 | 对外日产能 ds/qwen/wx |
|---|---|---|---|---|
| **起步** | **6** | 各 6 | 18 | ~180 / ~300 / ~300 |
| **目标** | **10** | 各 10 | 30 | ~300 / ~500 / ~500 |

> "1 IP 挂 3 个不同平台账号"最省 IP:**IP 数 ≈ 每引擎账号数**(不是总账号数)。
> 同平台两个号不要挤一个 IP。

## 五、代理选型

| 维度 | 国内长效独享静态 | Bright Data ISP |
|---|---|---|
| IP 质量 | 中(住宅/机房混) | 高(ISP 住宅级,干净) |
| 境内 | 一定境内 | 需确认(默认按可用) |
| 抗风控 | 中 | 高 |
| 计费 | **按通道/月,流量不限,固定** | 按 IP + 流量(GB) |
| 价格 | 便宜(~¥49/通道/月) | 偏贵(美元) |
| 粘定 | 静态天然粘 | 加 `-session-<账号id>` 粘 |

**配置要点(两家通用):中国大陆 · 住宅/ISP · 静态或长效粘性(≥几小时)· 独享 · 带宽 ≥5M。**

**不要选**:短效代理、按请求换 IP、隧道(轮换出口)、动态 IP。

**性价比判断**:
- 浏览器跑 AI 网页**以文本为主、流量中低**(几 GB/月);
- **走量主力 → 国内长效独享静态**(流量不限、便宜、一定境内);
- **精品 / 抗封关键账号 → Bright Data ISP**(质量高,小批量用,避免大流量)。

Bright Data 粘定示例:
```
--proxy brd.superproxy.io:33335 \
--proxy-user <ZONE-USER>-country-cn-session-acct<账号id>:<PASSWORD>
```
同一 `session-acct<id>` 锁定同一 IP;`session-id = 账号id` 即可一账号一稳定 IP。

## 六、费用报价

```
月费 = IP代理(通道数 × 单价) + 账号成本(一次性/养号) + API调用费(按量)
通道数 = 每引擎账号数(3 合 1)
```

| 项 | 起步(6 通道/18 号) | 目标(10 通道/30 号) |
|---|---|---|
| 国内长效独享静态 @¥49/通道/月 | **~¥294/月** | **~¥490/月** |
| 账号(补 qwen/文心) | 一次性补 ~10 个 | 一次性补 ~24 个 |
| 元宝 API(SearchPro) | 按调用次数 | 同 |
| 豆包 API(ARK) | 按 token | 同 |
| deepseek 合成(OpenRouter,元宝用) | 按 token | 同 |
| 服务器(worker) | 已有 | 已有 |

**主成本是 IP:起步 ~¥300/月、目标 ~¥490/月(流量不限)。** 账号 + API 为次要 / 按量。

## 七、落地动作(摸清 → 上量)

1. 买 **6 通道国内长效独享静态** + 补 qwen/文心账号到 ~6 个。
2. browser-service 接 **"按账号粘定代理"**(`create_headed_page`/`create_stealth_page` 加 proxy,session-id=账号id)。
3. 跑一周,**看账号池 captcha / login_lost 信号** → 反推每个号真实安全量。
4. 据实测把 **deepseek 日上限从 30 提到 ~150–300**(4→10 IP 后安全)。
5. 稳了扩到 **10 通道 / 30 账号**;对外按客户增长继续加。
