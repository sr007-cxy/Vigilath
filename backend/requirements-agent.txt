# ★ The transitive dependency openai must be pinned. The line above doesn't constrain it, so builds at different times resolve different versions:
#   in 2026-08 the CN production container image resolved openai 3.3.1, while the test host and prod EC2 venvs had 2.41.0.
#   openai>=3's built-in httpx_aiohttp references aiohttp.SocketTimeoutError at import, an attribute only in
#   aiohttp >= 3.10; with the old aiohttp 3.9.1 pin this meant:
#     import openai -> AttributeError -> build_agent raises -> /api/agent/chat always 503
#   while /health doesn't import pydantic-ai, so the container still reports healthy -- same commit, two behaviors,
#   depending only on which day the environment was installed. Without pinning, this kind of drift will happen again.
#   aiohttp is now >=3.14.3, so openai>=3 is no longer blocked by that, but it is untested here: keep <3 until verified.
openai>=2,<3
